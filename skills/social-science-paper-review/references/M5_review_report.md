# M5 Review Report

## 状态检查

检查 `state/M5_review_report.md` 是否存在。
- 存在 -> 读取并跳过本模块
- 不存在 -> 执行以下逻辑

## 输入

| 字段 | 类型 | 来源 | 说明 |
|------|------|------|------|
| `review_brief` | JSON | `state/M1_review_brief.json` | 审阅场景和限制 |
| `claim_map` | JSON | `state/M2_claim_map.json` | 主张和证据链 |
| `method_audit` | JSON | `state/M3_method_audit.json` | 方法审查 |
| `positioning_audit` | JSON | `state/M4_positioning_audit.json` | 文献、贡献、伦理审查 |

## 执行

1. 先给总体判断：论文贡献是否清楚、证据是否足够、主要风险是什么。
2. 输出严格审稿意见：摘要、主要优点、主要问题、次要问题、作者问题、录用/修改建议。
3. 输出修改指导：按优先级写“先改什么、为什么、怎么改、改到什么程度”。
4. 对每个重大问题标注证据位置：章节、表图、段落、引文或作者主张。
5. 单列结构与表达审查：文章主线、段落承接、错字、衍字、病句、句式不通畅、连接词/承接词过多或过少。
6. 把建议分成三层：必须改、建议改、可选优化。
7. 如果材料不完整，明确哪些判断只是暂定，哪些需要全文/附录/数据才能确认。
8. 语气保持审稿式：严格、具体、可执行，不羞辱作者，不写空泛鼓励。

## 输出

- **文件**: `state/M5_review_report.md`
- **格式**: Markdown
- **结构**:
```markdown
# 社科论文审阅报告：[题目]

## 总体判断
[2-4 段：研究问题、贡献、证据强度、最大风险、建议处理结果]

## 审稿结论
- **建议**：[Accept / Minor Revision / Major Revision / Reject / 无法判断]
- **置信度**：[High / Medium / Low]，原因：[...]
- **贡献等级**：[Strong / Solid / Incremental / Unclear / Below threshold]
- **主要处理意见**：[...]

## 主要优点
1. **[优点标题]**：[具体说明，指出论文位置和价值]

## 主要问题
1. **[问题标题]**
   - 问题：[具体是什么]
   - 影响：[为什么影响论文中心结论]
   - 修改指导：[作者应该怎样改]
   - 优先级：[必须改 / 建议改]

## 方法与证据审查
- **研究设计匹配**：[该设计是否能回答研究问题；定量/定性/混合/综述/理论路径是否选对]
- **方法论理由**：[作者是否说明为什么这种方法适合研究问题、理论/知识主张和材料性质；缺失时如何补写]
- **证据可信度**：[样本、材料、测量、识别、解释过程、稳健性或三角验证是否足以支撑结论]
- **修改指导**：[作者应如何调整方法说明、补充证据、收窄结论或重写方法论段落]

## 文献定位与理论贡献
[指出贡献是否成立、缺哪些文献、引言和讨论如何重写]

## 结构、脉络与表达
- **文章主线**：[研究问题、理论、方法、证据、结论是否连成清晰脉络]
- **论证链条**：[哪些环节跳跃、重复、断裂或没有回扣中心问题]
- **引用解释**：[哪些引用只是堆砌，哪些地方需要加入作者自己的解释、比较或综合]
- **语言机械问题**：[错字、衍字、病句、句式不通畅]
- **连接与承接**：[连接词/承接词是否过多造成堆砌，或过少造成段落跳跃；给出具体删减或补充建议]

## 次要问题
- [表达、结构、表图、术语、引用、格式等]

## 作者修改路线
1. **第一轮：救中心论点** [...]
2. **第二轮：补方法和证据** [...]
3. **第三轮：修文章脉络和引用解释** [...]
4. **第四轮：清理语言和承接** [...]

## 需要作者回答的问题
1. [...]
```

## 回滚
