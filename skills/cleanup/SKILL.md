# Cleanup

在任务推进到新阶段或准备完成时，收拾本次任务留下的过程文件。不删除已完成、已交付或用户可接受的正式产物。不做功能判断，不做优化或重构。

## 强制规则

**每次任务完成时必须自动加载并执行本 skill。** 这不是可选项——在声称"完成"、"好了"、或准备结束回复之前，必须先完成清理步骤。如果忘记执行，清理步骤本身也是任务的一部分，不能以"任务已完成"为借口跳过。

- 涉及 `npm install`、`pip install`、`mkdir`、编译、构建、临时脚本等操作的任务，100% 会产生需要清理的过程文件。
- 如果清理后发现没有可清理内容，输出 `Status: cleaned (nothing to clean)`。
- 不要在最终回复中询问用户"是否需要清理"——直接执行。

## 触发

- 一个阶段完成，准备进入下一阶段前
- 任务完成，最终回复前
- 用户要求停止、放弃、撤回、重来
- 用户拒收当前产出，并希望丢弃或收拾本轮结果
- agent 发现自身执行错误，需要清理错误产物并重试

清理只处理过程文件；阶段是否完成由对应工作流决定。

## 可清理内容

只处理能确认属于本次任务的内容：

- 临时文件、debug log、临时截图、失败导出物、缓存、`.DS_Store`
- 编译运行时残留：`__pycache__/`、`*.pyc`、编辑器备份 `*~`、`*.bak`、`*.orig`
- 临时调试代码：`print()`、`console.log()`、`debugger`、`pdb.set_trace()`
- 本次为调试、试验或失败方案生成且未被采用的空目录、未引用文件
- 本次创建的一次性处理脚本（如数据处理、文档转换、临时自动化），任务完成后不再需要
- 本次改动造成的未使用 import
- 硬编码密钥、测试账号、误提交配置、假数据
- 本次安装但未使用的依赖或无效锁文件变化

正式产物保留：用户要的代码、文档、图片、表格、报告、配置等，只要是完成任务所需或用户可接受的结果，就不是过程文件。不确定归属的文件保留并报告。

## 正常清理

1. 查看 diff、输出文件和阶段产物。
2. 删除或修正明确冗余/错误的内容。
3. 轻量复查，例如 `git diff`、目录列表或必要格式检查。

## 中断/拒收

- 删除本次生成且不再需要的过程文件和未接受产物
- 有可靠基线时，只复原本次 agent 未被接受的既有文件改动
- 文件被用户改过、原始内容不确定、归属不明时，不覆盖、不删除
- 不使用会扩大影响范围的批量回退命令

可靠基线包括 git diff、任务前备份、明确变更清单或可逆补丁。

## 输出

简单任务可用一句话；复杂任务输出 `Cleanup Report`。

报告必须包含：

- 已删除/已修正/已复原的内容
- 保留待确认的内容及原因
- `Status: cleaned | interrupted-cleaned`

## 约束

- 每个清理动作都要能说明“为什么属于本次任务且不再需要”
- 敏感信息只说已移除，不复述密钥内容
