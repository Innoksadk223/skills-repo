# Cleanup

留下最终产品和仍有用途的资料，清理本次任务确认无用的过程产物。避免误删优先于清理彻底；检查结束不代表必须有文件可删。

## 按用途分类

| 类型 | 含义 | 处理原则 |
|------|------|----------|
| 运行残留 | 本次运行产生的缓存、失败产物和临时调试残留 | 确认归属、无后续用途且未被使用后可直接清理 |
| 结果制作工具 | 为获得本次结果制作的一次性小工具、脚本和实验文件 | 确认结果已交付且不依赖它们后，建议删除，先取得用户确认 |
| 验证与观察产物 | 测试、性能分析、浏览器操作产生的报告和观察记录 | 交付或审查需要的保留；仅供过程查看且已无用途的，列明后询问删除 |
| 输入与中间材料 | 临时获取的输入副本、转换材料和未采用的方案 | 原始资料和唯一副本保留；确认来源可恢复、无后续用途后询问删除 |
| 任务状态与恢复资料 | Agent 或工具保存的计划、会话、检查点和恢复记录 | 默认保留；确认不再承担恢复、审查或后续执行作用后才提出删除 |

最终产品、可复用测试及其依赖不属于清理对象。生成代码、配置、数据库、依赖与锁定信息、补丁和备份都可能有长期价值，默认保留。详细边界见 [references/file-types.md](references/file-types.md)。

## 防误删边界

- 确认具体文件由本次任务产生且没有用户或其他 agent 的后续修改；无法确认就保留。
- 检查是否用于产品运行、构建、部署、测试、文档、审查或用户后续修改。没有搜索到引用不等于没有用途。
- 不凭文件名、后缀、隐藏目录、未跟踪状态或“自动生成”判断可删；不整目录清空工具状态或全局缓存。
- 检查路径是否为链接，避免穿透链接删除其他位置的内容；仍被进程使用或承担恢复作用的文件保留。
- 不把清理扩大为代码重构、依赖卸载、环境重置或回滚。禁止仓库级清空与通配符批量删除。
- 用户对具体清单已明确授权时直接执行，不重复询问；新增路径或影响范围需重新说明。没有答复不算同意。

## 操作流程

1. 根据本次操作记录与工作区差异确定候选文件，仅检查明确相关的路径。
2. 按用途分类，说明来源、当前用途以及删除影响；不确定项保留。
3. 清理符合条件的运行残留。其余拟删除项汇成一份具体清单，列出路径、用途、理由与影响后请求确认。
4. 获得确认后只删除授权范围；未确认的文件保留，继续交付已完成的任务结果。
5. 复查目标路径和差异，确认最终产品、正式测试及用户资料没有受影响。不为清理额外启动测试或构建。

中断或重试时同样遵循这些边界，尤其保留仍有诊断和恢复价值的资料。

## 报告

简要说明已清理、保留及待确认事项，并报告复查结果。无清理对象时直说，无需为凑清单扫描无关目录。格式见 [references/report-template.md](references/report-template.md)。
