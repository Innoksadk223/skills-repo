# 常见反模式

## 反模式 1：巨无霸 SKILL.md

**症状**：SKILL.md 超过 500 行，包含所有执行逻辑

**后果**：每次加载花 2000+ token，改一个小步骤 Agent 要重读全文

**修正**：SKILL.md 只留调度逻辑（< 100 行），具体步骤拆分到 `references/M1_*.md`

---

## 反模式 2：模块间直接引用

**症状**：
```
# M3_draft.md
执行第 3 步时，参考 M2 中第 47-52 行的那个 for 循环...
```

**后果**：改 M2 的任何细节都可能让 M3 失效，调试时要在多个文件间跳转

**修正**：M2 把结果写入 `state/M2_outline.json`，M3 只读这个 state 文件

---

## 反模式 3：一个模块干多件事

**症状**：
```
# M2_process.md
1. 解析用户输入
2. 调用 API 搜索文献
3. 格式化引用
4. 生成大纲
5. 渲染预览
```

**后果**：任何一步失败都要重跑全部 5 步，无法单独调试

**修正**：拆成 M2a_search、M2b_format、M2c_outline 三个模块

---

## 反模式 4：没有回滚策略

**症状**：模块失败后 state/ 中残留半成品，Agent 分不清是"已完成"还是"做了一半坏了"

**后果**：断点续跑逻辑判断错误，跳过本该重跑的模块

**修正**：每个模块写清楚"回滚"段，列出失败时需清理的文件

---

## 反模式 5：state 文件格式不统一

**症状**：M1 输出 JSON，M2 输出纯文本，M3 输出 YAML，没有结构约定

**后果**：后续模块需要写 3 种解析逻辑

**修正**：全部用 JSON 或全部用 YAML 前置声明，在 SKILL.md 的模块清单中标注格式
