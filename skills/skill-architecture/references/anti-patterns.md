# 常见反模式

## 1：巨无霸 SKILL.md

**症状**：SKILL.md >500 行，包含所有执行逻辑
**后果**：每次加载 2000+ token，改一步要重读全文
**修正**：管道型->拆到 `references/M*.md`，SKILL.md 只留调度器；操作型->按操作拆 references/（见 skill-creator 渐进披露）

## 2：模块间直接引用

**症状**：M3 写"参考 M2 中第 47 行的 for 循环"
**后果**：改 M2 任何细节都可能让 M3 失效
**修正**：M2 结果写入 `state/M2_xxx.json`，M3 只读 state 文件

## 3：一个模块干多件事

**症状**：一个模块同时搜索、格式化、生成大纲、渲染预览
**后果**：任何一步失败全量重跑，无法单独调试
**修正**：按职责拆成 M2a_search、M2b_format、M2c_outline

## 4：没有回滚策略

**症状**：模块失败后 state/ 残留半成品，Agent 分不清"已完成"还是"做了一半"
**后果**：断点续跑误判，跳过本该重跑的模块
**修正**：每个模块写「回滚」段，列出失败时需清理的文件

## 5：state 文件格式不统一

**症状**：M1 输出 JSON，M2 纯文本，M3 YAML
**后果**：后续模块要写多种解析逻辑
**修正**：格式统一，在模块清单中标注

## 拆分/合并判断

**该拆**：步骤 >7、模块含多职责、各步需独立调试、频繁单独修改某步
**该合**：两个模块总一起执行、共享全部 state、中间 state 无独立复用价值
**红线**：模块数 >7 说明该拆成两个 skill
