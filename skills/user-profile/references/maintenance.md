# 用户画像维护

准备维护画像或处理异常时阅读；日常使用与收尾回顾以 [SKILL.md](../SKILL.md) 为准。下面命令使用默认安装路径，安装位置不同时替换为实际路径。

## 记录判断

本节只判断哪些信息够格成为候选。是否写入由用户在候选清单里逐条选定，规则见 [SKILL.md](../SKILL.md) 的「写入确认」。

### 新增与修正

可以记录身份背景、分领域认知基础、行为习惯、沟通与决策方式、审美与内容偏好、反感，以及影响多个任务的阶段性协作需求。分类可扩展，只保留对协作有效的信息，不为填满分类而猜测。

身份不等于能力。按具体领域记录熟悉什么、哪些概念需要解释；不因一次提问判断整体能力。明确表达的长期偏好或反感，一次即可成立，但写入仍由用户选定。推断须来自多个独立情境中反复一致的选择和反馈，考虑任务限制，保留范围、不确定性和简短依据；旧画像、AI 输出不算新证据。

不记录具体任务的题目、研究对象、素材、项目细节、临时进度、结论、仅限当次的要求、临时角色、未确认方案、他人观点或假设例子。不从处理过某个主题推断用户长期兴趣、身份、信念或立场。例如，“正在写《礼记》论文”不入画像；用户明确自述的长期研究方向可以记录，但仍不能带入无关任务。已确认的本次设计决定，也不自动成为长期个人特点。

健康、家庭、财务等敏感私人情况，写入前取得明确确认；密码、密钥、验证码不存。所有自述均须通过跨任务相关性与隐私检查。

用户明确纠正或表达长期变化时更新对应条目；新证据可修正推断和范围，重复信息合并。临时要求不覆盖长期偏好，不用旧画像反驳用户对自己的明确说明。

保留反感强度：“不太喜欢”是尽量避免，不是禁令；“不要，除非……”保留例外。对单个作品的批评不扩大为普遍厌恶，不猜测原因或人格。新旧信息确有歧义且影响当前处理或既有记录时才询问，不编造条件调和矛盾；无关紧要的模糊线索暂不记录，不建立候选库。

阶段性协作需求保留时间依据，有明确结束时间则记录。到期后不再作为当前事实使用；有效性有疑问时，在再次相关时确认，不因长期未提及就断言已结束。

更新时整理相关部分的重复、冲突或过时内容；用户主动要求时可整体整理。不每轮全文重写，不为了“有更新”而改措辞或追加历史。

### 删减与忘记

普通删减包括去重、移出已失效内容，以及容量不足时淘汰低价值信息，可保留必要的简短变更依据。去重、移出失效内容同属内容变更，先列入候选由用户选定；用户自己要求的删除、忘记不算。不得仅因“很久没提”认定失效。

用户要求忘记时，从当前画像及本技能管理的相关历史中一并移除，包括同义表述、合并记录和工作草稿中的对应内容。不在说明或新日志中复述，不从旧记录恢复；可仅留下不含被忘记内容的操作说明。存在暂存残留时先按“异常处理”核对并清理，未处理完不能声称忘记完成。不能声称同时清除了平台聊天、模型服务方记录或外部备份。

明确禁止事项及用户指定“必须保留”的条目是保护项，不得因容量自动淘汰；用户主动纠正或要求忘记时仍可修改、删除。保护范围只覆盖已表达的约束，不随意升级普通偏好。

## 记录格式

当前画像用 Markdown 简短分组，仅有内容时设组：背景与认知、习惯与偏好、反感与边界、阶段性协作需求；需要时可调整分类。条目使用稳定编号，更新沿用原编号。

```text
- P001｜<内容>；范围：<场景>；性质：明确陈述/推断；依据：<简短描述>；更新：YYYY-MM-DD
```

必要时补充 `保护：明确禁止/用户指定`、强度、最后确认时间、结束时间；明确禁止事项不能漏标保护。不写人格分数、置信度分数或整段聊天。格式示例不是用户资料。

历史用简短条目：`时间｜编号｜新增/更新/合并/移除｜必要的变化与依据`。忘记操作不复述被忘记内容。

## 提交更新

先列出候选并向用户要哪几条，未被选中的不写入；用户主动要求删除、纠正、忘记时目标已明确，跳过此步。之后按下列顺序提交：

1. 用 `read --history` 重读两份最新内容，保存输出的 `version`。按记录规则和用户选定整理完整候选文本，未改动内容保持原样。不要只读取版本却复用旧草稿。
2. 候选文件仅放会话临时目录，以 UTF-8 保存，不做正式数据备份或画像归档。下面命令中的路径和版本须替换为实际值；候选文本虽整份提交，只改必要条目。
3. 通过 `commit` 提交，禁止用 Edit、Write、重定向等直接修改正式数据：

```bash
python3 ~/.agents/skills/user-profile/scripts/profile_store.py commit \
  --expect '<read 输出的 version>' \
  --profile-file "$PI_SCRATCH_DIR/profile-next.md" \
  --changes-file "$PI_SCRATCH_DIR/changes-next.md"
```

4. 容量或版本检查不通过，两份原文件不变。超限时按下节整理；版本冲突时重新读取两份内容再合并，不仅替换版本号重试。不要为了腾空间先清空正式数据。
5. 成功后 `read --history` 回读与候选对照，再简短告知实际变化。删除本次不再需要的私人候选副本，不保留含已忘记内容的工作草稿。没有变化的提交不会重写文件，不应为此追加历史记录。

脚本用短时目录锁及内容版本检查防止遵守入口的并发写入互相覆盖。单个文件原子替换，两个文件不是数据库事务；文件错误可能导致部分写入，应停止、检查两份实际内容，不能宣称整体成功或无变化。手工修改可绕过入口，所以读取也检查容量。

## 容量整理

画像与历史分别不超过 4000 个 Unicode 码点。按最终 UTF-8 解码文本计数，标题、字段名、空格、标点及所有换行都计入，CRLF 算两个字符；不是字节数、显示字形数或 token 估算。4000 可写，4001 拒绝。

画像先无损精简、去重、移出已失效内容，再按证据强弱和协作相关性淘汰低价值条目。不采用数字评分，不删保护项来腾空间，不丢掉有效的适用条件或例外。

历史先合并旧记录，再淘汰低价值记录；保留必要的变化依据，不编造原因、不截断半条记录，不把推断升级为事实。被普通淘汰的历史不能作为恢复画像的依据；须重新满足写入规则。

只剩保护项仍装不下时，拒绝写入并请用户决定。不得抬高上限、增加归档或另建文件隐藏溢出内容；工作草稿不能成为第三份长期记忆。

## 初始化与缺失恢复

首次安装先说明数据位置并取得用户确认；只建立空标题，不搬入旧认知或讨论示例。已有数据丢失时，先报告缺失项并确认恢复方案，不把缺失视为“没有资料”。只有用户明确同意空白补缺时才运行：

```bash
python3 ~/.agents/skills/user-profile/scripts/profile_store.py init
```

`init` 只建立缺失的目录或文件，初始两份文件各有标题、无个人条目；不覆盖已有文件，也不验证其正文。完成后运行 `read --history` 确认实际状态，再进入正常维护。若需从用户提供的资料恢复，补缺后核对资料并通过 `commit` 提交；用户要求忘记的内容不能借恢复重新写回。

初始化中断也可能只建好一份文件；报告实际状态，重新运行 `init` 只补缺失部分，不清空已有内容。普通 `read`、`check`、`commit` 不自动创建数据。

## 异常处理

- `BUSY`：目录正被维护，待占用结束后重新读取；不要删目录或锁。
- `STALE_VERSION`：重读两份内容，再合并修订稿；不只替换版本号。
- 超限：用 `check` 取得容量、状态及版本，停止正常加载。仅为修复，按权限有界读取两份当前内容（含未超限的一份），原样保留无需修改部分，再通过 `commit` 缩减。
- 缺失、编码或文件类型错误：停止正常加载并说明原因；缺失按上节处理，不猜测、截断或覆盖原文件。
- `WRITE_ERROR` 或写后不一致：检查两份实际文件，可能部分写入；不要盲目重试或宣称原文件均未变化。

`check` 不输出正文；超限或存在暂存残留时仍输出 JSON 状态，但退出码为 1。先检查输出，不把这个退出码误判成“没有拿到状态”。

### 暂存残留

强制终止可能留下数据目录内的 `.user-profile-*` 暂存文件，包含完整或部分候选正文。`read`、`commit`、`init` 遇到此类路径会停止并提示；`check` 列出文件名，不显示正文。该前缀保留给脚本暂存，不放其他资料。

先核对列出的路径、归属和用途；不能仅凭前缀认定可以删除。不确定则保留并询问，确认是无恢复用途的本技能残留、获准清理后，逐个传入实际文件名，不使用通配符：

```bash
python3 ~/.agents/skills/user-profile/scripts/profile_store.py clean-staging \
  --file '.user-profile-实际文件名'
```

可重复传入 `--file`。命令持有独占锁，只接受数据目录内指定的暂存名称、当前用户所有的单链接普通文件；不处理目录、符号链接或正式数据。清理后重新 `read --history` 核对两份实际内容，再继续维护。它只删除获准的残留，不回滚或恢复正式文件。

## 验证

只有获准时才运行自检，使用虚构数据并指定会话临时目录：

```bash
python3 -B ~/.agents/skills/user-profile/scripts/profile_store.py self-test --scratch "$PI_SCRATCH_DIR"
```

自检不触碰默认数据，会自动清理测试目录。`--data-dir` 仅用于明确授权的替代位置或虚构数据检查，不用于分散或绕过真实画像容量。
