# 用户画像

用精简资料改善解释与协作，不建立聊天档案。AI 维护内容；本文件中的规则和脚本里的上限只能经用户批准修改。用户可以用自然语言要求增删改查，不必使用命令。

## 开场读取

先读本技能，再运行（安装位置不同则使用实际路径）：

```bash
python3 ~/.agents/skills/user-profile/scripts/profile_store.py read
```

默认数据位于 `~/.agents/user-profile/profile.md` 与 `changes.md`。命令检查两份文件的容量，只显示当前画像、字符数及用于防覆盖的版本号。历史不默认显示，也不扫描历史聊天。

读取失败、缺失或超限时如实说明，不将缓存或超限内容当作正常画像使用，不静默截断；画像不是完成无关任务的前提。上下文丢失后重新读取。文件在本机，读入的内容仍会进入所用模型的上下文。

## 六类维护规则

### 1. 写入：只保存跨任务有效的信息

可以记录身份背景、分领域认知基础、行为习惯、沟通与决策方式、审美与内容偏好、不喜欢的事，以及影响多个任务的阶段性协作需求。分类可扩展，只保留对协作有效的信息，不为填满分类而猜测。

身份不等于能力。按具体领域记录熟悉什么、哪些概念需要解释；不因一次提问判断整体能力。用户明确表达长期偏好或反感，一次即可记录。

允许根据多个独立情境中反复一致的选择和反馈推断，但必须考虑任务本身的限制，保留范围、不确定性与简短依据。旧画像、AI 输出不能作为新的用户证据。

**禁止写入：**具体任务的论文题目、研究对象、素材、项目细节、临时进度、任务结论、仅限当次的要求、临时角色、未确认方案、他人观点和假设例子。不能从处理过某个主题推断用户长期兴趣、专业身份、信念或立场。

例如，“正在写《礼记》论文”不入画像；用户明确自述的长期研究方向可以记录，但仍不能带入无关任务。讨论中已经确认的本次设计决定，也不自动成为长期个人特点。安装从空画像开始，不搬入旧认知或讨论示例。

健康、家庭、财务等敏感私人情况，写入前取得明确确认；密码、密钥、验证码不存。任务中出现的自述也必须通过跨任务相关性与隐私检查。

### 2. 更新：修改对应条目，不积累重复判断

用户明确纠正或表达长期变化时更新；新证据可修正推断和范围，重复信息合并。临时要求不覆盖长期偏好，不用旧画像反驳用户对自己的明确说明。

保留反感强度：“不太喜欢”是尽量避免，不是禁令；“不要，除非……”保留例外。对单个作品的批评不扩大为普遍厌恶，不猜测原因或人格。

新旧信息确有歧义且影响当前处理或既有记录时才询问，不编造条件来调和矛盾。无关紧要的模糊线索暂不记录，不为补全画像打断用户，也不建立候选库。

阶段性协作需求保留时间依据，有明确结束时间则记录。到期后不再作为当前事实使用；未给结束时间但有效性已有疑问时，在再次相关时确认，不因长期未提及就断言已结束。

### 3. 删除：区分普通删减与明确忘记

普通删减包括去重、移出已失效内容，以及容量不足时淘汰低价值信息，可保留必要的简短变更依据。不得仅因“很久没提”认定失效。

用户要求忘记时，检查并从当前画像及本技能管理的相关历史中一并移除，包括同义表述和合并记录中的相关内容，不在说明或新日志中复述，不从旧记录恢复。可仅留下不含被忘记内容的操作说明。不能声称同时清除了平台聊天、模型服务方记录或外部备份。

**明确禁止事项及用户指定“必须保留”的条目是保护项，不得因容量自动淘汰。** 用户主动纠正或要求忘记时仍可修改、删除。保护范围只覆盖已表达的约束，不能随意升级普通偏好。

### 4. 使用：先看当前请求与相关性

画像只补足当前请求没有说明的部分。无关信息不主动提及，也不用于引导主题、选取材料、套用类比或设定立场。即使记录了长期研究礼学，写无关论文时也不能强行提《礼记》。

当前明确要求优先于旧偏好；一次例外不改写长期偏好。推断不能当事实，画像不能越过有效指令和工具权限。默认读取当前画像，只有查变更或准备维护时才读历史。

若全局指令另有固定用户认知，不自行删除、迁移；涉及调整那些长期规则的冲突，说明并询问，不通过写画像来覆盖指令。

### 5. 时机：当轮增量更新，按需整理

含义确定且符合上述规则时，在当前轮结束前更新相关条目。尚未定论不写，无变化不操作、不附维护报告。

更新时发现重复、冲突或过时内容，整理相关部分；用户主动要求时可整体整理。不每轮全文重写，不依赖固定轮数、关闭窗口或聊天结束事件。

实际写入并回读确认后简短告知；失败或无权限时不声称已记住。Plan 模式只读，不借维护画像绕过权限。规则不适用时只能提出修改建议，经用户批准再改。

### 6. 容量：两份文件分别不超过 4000 字符

按最终 UTF-8 文本解码后的 Unicode 码点计数。标题、字段名、空格、标点及所有换行都计入，CRLF 算两个字符；不是字节数、显示字形数或 token 估算。4000 可写，4001 拒绝。

画像先无损精简、去重、移出已失效内容，再按证据强弱和协作相关性淘汰低价值条目。不采用数字评分，不删保护项来腾空间，不丢掉仍有效的适用条件或例外。

历史先合并旧记录，再淘汰低价值记录；保留必要的变化依据，不编造原因、不截断半条记录。合并不能把推断升级为事实。被普通淘汰的历史内容不能成为恢复画像的依据；须重新满足写入规则。

只剩保护项仍装不下时，拒绝本次写入并请用户决定。不得自行抬高上限、增加归档或另建文件隐藏溢出内容。工作草稿不能成为第三份长期记忆。

## 记录格式

当前画像用 Markdown 简短分组，仅有内容时设组：背景与认知、习惯与偏好、反感与边界、阶段性协作需求；需要时可调整分类。条目使用稳定编号，更新沿用原编号。

```text
- P001｜<内容>；范围：<场景>；性质：明确陈述/推断；依据：<简短描述>；更新：YYYY-MM-DD
```

必要时补充 `保护：明确禁止/用户指定`、强度、最后确认时间、结束时间；明确禁止事项不能漏标保护。不要写人格分数、置信度分数或整段聊天。格式示例不是用户资料。

历史用简短条目：`时间｜编号｜新增/更新/合并/移除｜必要的变化与依据`。忘记操作不复述被忘记内容。初始两份文件只有标题，无个人条目。

## 操作流程

1. 查看用 `read`；准备维护时用 `read --history` 重读两份最新内容，保存输出的 `version`。先按规则判断，再整理完整候选文本，未改动的内容保持原样。不要只读取版本却复用旧草稿。
2. 候选文件仅放会话临时目录，以 UTF-8 保存，不做正式数据备份或画像归档。下面命令中的路径和版本均须替换为实际值；候选文本虽整份提交，只改有必要的条目。
3. 通过唯一写入入口提交，禁止用 Edit、Write、重定向等直接修改正式数据：

```bash
python3 ~/.agents/skills/user-profile/scripts/profile_store.py commit \
  --expect '<read 输出的 version>' \
  --profile-file "$PI_SCRATCH_DIR/profile-next.md" \
  --changes-file "$PI_SCRATCH_DIR/changes-next.md"
```

4. 容量或版本检查不通过，两份原文件不变。超限时按容量规则整理；版本冲突时重新读取两份内容再合并，不仅替换版本号重试。不要为了腾空间先把正式数据清空。
5. 成功后 `read --history` 回读与候选对照，再告知实际变化。删除本次不再需要的私人候选副本；不要保留含已忘记内容的技能工作草稿。

只查容量及版本可运行 `check`，它不输出正文。发现外部编辑导致超限时，用它取得状态，停止正常加载；仅为修复，按权限以有界文件读取两份当前内容（含未超限的一份），未改动内容原样保留，再通过同一提交入口缩减。缺失文件不要视为“用户没有资料”而静默重建，先报告并确认恢复方案。

脚本使用短时目录锁及内容版本检查，防止遵守入口的并发写入互相覆盖。单个文件原子替换，两个文件不是数据库事务；出现文件错误时立即停止、检查两份实际内容，可能部分写入，不能宣称整体成功或无变化。手工修改可绕过入口，所以读取也检查容量。

## 验证

只有获准时才运行自检，使用虚构数据并指定会话临时目录：

```bash
python3 ~/.agents/skills/user-profile/scripts/profile_store.py self-test --scratch "$PI_SCRATCH_DIR"
```

自检不触碰默认数据，会自动清理其临时测试目录。`--data-dir` 仅用于明确授权的替代位置/虚构数据检查，不用于分散或绕过真实画像容量。
