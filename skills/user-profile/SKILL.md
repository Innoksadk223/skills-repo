# 用户画像

用精简资料改善解释与协作，不建立聊天档案。AI 维护内容；技能规则和脚本上限只能经用户批准修改。用户可以用自然语言要求增删改查，不必使用命令。

## 开场读取

先读本技能，再运行（安装位置不同则使用实际路径）：

```bash
python3 ~/.agents/skills/user-profile/scripts/profile_store.py read
```

默认数据位于 `~/.agents/user-profile/profile.md` 与 `changes.md`。命令检查两份文件的容量，只显示当前画像、字符数及用于防覆盖的版本号。历史不默认显示，也不扫描历史聊天。上下文丢失后重新读取。

读取失败、缺失、超限或发现暂存残留时如实说明，按下方入口读取维护说明；不将缓存、超限内容当作正常画像使用，不静默截断或重建。画像不是完成无关任务的前提。文件在本机，读入的内容仍会进入所用模型的上下文。

## 写入确认

任何新增或修正都不由 AI 单方面落盘：判断完先出候选，是否写入由用户决定。

1. 按维护说明的判断规则筛出候选。
2. 每条带编号列出内容、范围、性质（明确陈述/推断）和简短依据，一次列全，问用户要哪几条。
3. 只把被选中的条目并入候选文本再 `commit`；用户没选、改选或说不写时不提交。
4. 候选只活在当轮对话和会话临时目录，不留待下次。

用户主动要求删除、纠正、忘记时，目标已由用户给出，不必再确认，直接按维护说明处理。

## 日常使用与记录边界

- 只保留跨任务有效的身份背景、分领域认知基础、习惯、偏好、反感及阶段性协作需求。具体任务的材料、进度、结论、临时要求和未确认方案不入画像。
- 用户明确表达的长期偏好一次即可成立，写入仍须用户选定；推断需要多个独立情境的证据，注明范围、不确定性和依据。旧画像、AI 输出不是新的用户证据；不从处理某个主题推断用户的身份、信念或长期兴趣。
- 健康、家庭、财务等敏感私人情况，写入前取得明确确认；密码、密钥、验证码不存。证据不足不写，不为补全画像打断用户，不建立候选库。
- 当前明确要求优先于旧画像，一次例外不改写长期偏好。无关画像不主动提及，不用于引导主题、选取材料、套用类比或设定立场；推断不能当事实。
- 用户要求忘记时，画像、相关历史和本技能工作草稿中的对应内容一并处理，不在说明或新日志中复述。明确禁止事项和用户指定保留的条目不得因容量自动淘汰。
- 画像不能越过有效指令和工具权限。Plan 模式只读；与全局固定用户认知冲突时，不自行删除、迁移或用画像覆盖指令，说明并询问。

## 收尾主动回顾

读过本技能后，在任务完成或阶段性交付、准备发送收尾回复前，主动回顾当前可见的本次任务交流，归纳用户透露的长期偏好、习惯、反感、认知基础及明确纠正。检查是否有值得新增的信息或需要修正的旧认识，不复述任务经过，不扫描旧会话。

回顾与写入分开：只有符合记录规则的新信息或修正才成为候选；已经记录的内容不重复追加。没有变化或依据不足就保持原样，无需报告。任务中已确定且符合规则的信息仍在当轮结束前列出候选，不必等到收尾。用户选定后写入并回读确认，再简短告知实际变化；失败或无权限时不声称已记住。不依赖固定轮数、关闭窗口或聊天结束事件。

## 显式触发：回顾、总结

用户说「回顾画像」「画像回顾」「总结画像」「画像总结」「回顾／总结一下你对我的了解」等带画像指向的说法时，按显式要求处理：先 `read` 当前画像，再回顾本次可见交流，按记录规则判断哪些长期偏好、习惯、反感、认知基础或纠正值得保留；按「写入确认」列出候选，用户选定后再按 [维护说明](references/maintenance.md) 的提交流程写入，完成后简短说明实际变化。没有新信息就说本次没有可记内容，不为回应而编造条目或重复已有条目。

- 可在任务中途使用，不受「收尾」时点限制；证据与隐私规则不变。
- 只回顾当前可见交流，不因此扫描旧会话。
- 必须带画像指向才触发；单独的「总结」「回顾」按当前任务正常理解（如总结一篇文章）。
- 只想查看而不修改时，说明只读意图（如「看看画像」），只概括现有条目，不写入；要看过往变更用 `read --history`。

## 按需读取

仅查看和使用当前画像时，到此即可。遇到以下情况，先读 [维护说明](references/maintenance.md)，再执行对应操作；同一任务已读过且内容未变化时无需重复加载。

| 情况 | 维护说明中的对应部分 |
| --- | --- |
| 准备新增、修正、删除、忘记或整理画像 | 记录判断、记录格式、提交更新；容量不足时再看容量整理 |
| 首次安装、文件丢失、读取或写入报错 | 初始化与缺失恢复、异常处理；暂存残留须核对后处理 |
| 获准运行自检 | 验证 |

查变更或准备维护时才读取历史；正式数据只通过脚本的 `init`（补缺）和 `commit`（更新）写入，不直接编辑。
