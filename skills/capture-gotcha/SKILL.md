# Capture Gotcha

把已验证的经验变成下一次任务开始时可直接执行的规则。价值在于稳定召回，所以每次相关任务都遵循固定顺序：**recall → 执行 → 按错误查询 → 修复验证 → 沉淀**。

记什么、写到哪个范围由 AI 依据下面的规则判断；脚本只保障容量、版本与写入安全，不核实事实，也不保证脱敏完备。

## 开始任务：强制 recall

只要任务涉及项目、终端、浏览器、MCP、文件系统、构建、测试、部署或工具调用，先运行：

```bash
python3 ~/.agents/skills/capture-gotcha/scripts/add_gotcha.py recall
```

不要凭记忆猜测文件位置，也不要因为任务看起来简单而跳过。无关键词 `recall` 按项目记忆、全局记忆的顺序输出正式经验；候选记忆不输出。

读完后检查三件事：

1. 当前任务是否命中某条规则。
2. 项目经验是否覆盖全局经验；冲突时遵守项目经验。
3. 是否有记忆中的命令、路径或工具限制需要在动手前调整。

遇到具体错误时，再用关键词查询：

```bash
python3 ~/.agents/skills/capture-gotcha/scripts/add_gotcha.py recall '关键词或错误码'
```

项目或全局文件超过 4000 码点时，`recall` 会明确报告该文件的路径与字符数并以非零退出，**不会**把超限文件截断后当作正常记忆输出；此时先按「维护」一节修复，再继续任务。记录格式读不出结构时同样只报问题，不静默当成没有内容。

## 判断记忆范围

正式记忆两处，候选一处：

- **项目记忆**：`<项目根>/.agents/gotchas.md`。当前代码、配置、目录结构、业务约定或项目工具链特有的经验写这里。
- **全局记忆**：`~/.agents/gotchas.md`。脱离当前项目仍成立的本机环境、通用工具行为、权限、代理、路径、shell 和包装层经验才写这里。
- **候选记忆**：`<项目根>/.agents/gotchas-candidates.md`。范围或结论还没确认时先写这里，不参与 `recall`。

问自己：换到一个完全无关的项目，这条经验是否仍然成立？是，才考虑全局；否，写项目。项目特例绝不能污染全局。无法判断范围时，先写项目候选，验证后再提升。

## 从事故提炼成规则

只压缩事故经过是不够的：入库的是**可迁移的操作规则**，不是某次事故的复述。写之前按下面几条自查，不合格就先提炼或放进候选。

1. **以行动规则命名**，不以某次事故命名。「区分操作失败与空结果」是规则，「curl 那次报错」是事故。
2. **保留共同机制，剔除偶然细节**：工具名、路径、版本、具体数值属于偶发，一般不写进规则；但决定适用边界或动作的那几个细节必须留下，不能为了抽象而丢掉限制条件。
3. **有明确触发条件和具体可执行动作**，能改变下一次的行动。「谨慎操作」「注意验证」这类口号和泛泛常识不收——读者看完不知道要做什么。
4. **概括范围不得越过证据**：只有一个工具的案例，不得写成「所有工具都这样」。机制还没弄清的写项目候选，不泛化；同一机制有对照或多案例时才合并成一条；原则性建议和已验证事实分开写，不混在同一句里。
5. **按共同机制合并**，不是仅按工具名合并；同一个工具但根因不同的两条，不硬合并成一条。
6. **正文写规则，验证只留日期与最短案例证据**，不把日志原文搬进来。把事故缩写成「XX 报错」也不等于提炼。
7. **全局优先写跨项目、跨工具可迁移的操作规则**；项目长期特有的约束留在项目记忆；工具完整使用说明属于技能文档，不重复记一份。确有必要的本机限制可以保留，但要写清环境条件，不当成永久常量。
8. **正式记录必须满足**：有证据、已执行验证、对将来有用；主动成功验证也可以，不必先失败一次。普通 bug 只有在提炼出可复用规则后才值得收。临时进度、任务素材、一次性远端故障、原始日志、已有文档重复内容、凭证等敏感信息、以及猜测，都不收。候选不参与 `recall`；转正必须先补足验证，脚本不会替你核实事实。
9. **维护先提方案**：精简、合并或删除前先向用户说明保留什么、删什么、合并成什么样，获准后再提交。不得借「要满容量了」静默删除记录，也不得无限归档或私自改上限；保留仍有效的边界与证据时间。

格式示例（只演示写法，不是要记的内容）：

```text
### 区分正常空结果与操作失败
- 适用: 读取、查询、外部调用既可能返回空结果也可能执行失败，需要区分两者时
- 做法: 让成功但为空与执行失败返回不同状态；不要把异常统一捕获成空结果，否则调用方无法判断。根因：两者在调用方需要不同处置。
- 验证: 2026-09-27；AppleScript 缺失文件、空文件与权限不足，实测分别报错，旧写法把三种情况都当成空结果
```

## 什么时候记录

正式记录必须同时满足：

- 有真实证据：错误原文、日志或可重复的实测结果，而不是转述或想象。
- 结论已经明确到能直接执行，而不是「可能是……」，并且已按上一节提炼成规则。
- 已执行验证并确认结果，或属于**主动验证成功**得出的工具行为、环境限制、项目约束（这类不必先失败一次）。
- 描述的是可复用的约束，能改变未来任务的行动。

明确不收：

- 临时进度、任务细节、只对本次对话有意义的中间状态。
- 泛泛的知识、建议或最佳实践，不能落到具体触发条件上的。
- 原始日志堆砌、一次性远端故障、网络抖动等无法复现的偶发问题。
- 现有技能文档已经写清的内容，不重复记一份。
- 密码、令牌、私钥等敏感凭证；脱敏只是兜底，写之前应主动去掉。

不确定的经验写项目候选：

```bash
python3 ~/.agents/skills/capture-gotcha/scripts/add_gotcha.py add \
  --scope candidate --title '可迁移的规则名' --when '触发条件与适用边界' \
  --action '可执行动作' --verified '2026-01-01 最短验证依据'
```

候选不参与任务开始时的读取。相同问题再次出现且解法稳定后，用唯一关键词提升：

```bash
python3 ~/.agents/skills/capture-gotcha/scripts/add_gotcha.py promote '关键词' --scope project
python3 ~/.agents/skills/capture-gotcha/scripts/add_gotcha.py promote '关键词' --scope global
```

转正要求补足证据，而不是只把内容挪个位置。`promote` 必须唯一匹配一条候选，写入成功后才从候选文件移除该条；目标容量不足或候选格式不符时整体拒绝，候选保留不丢。

## 写入

```bash
python3 ~/.agents/skills/capture-gotcha/scripts/add_gotcha.py add \
  --scope project --title '可迁移的规则名' --when '触发条件与适用边界' \
  --action '可执行动作；根因仅在影响动作时补一句' \
  --verified '2026-01-01 最短验证依据'
```

记录格式固定为 `# Gotchas` 加每条 `### 标题` 与其后的 `适用`、`做法`、`验证` 三个字段；`--verified` 省略时只写入当天日期，最好补上最短验证依据。字段名用半角冒号，全角冒号也接受（中文输入法正常写法不会丢数据）。标题写规则名而不是事故名；`验证` 必须以 `YYYY-MM-DD` 日期开头。三个字段值都必须是**单行**：含换行会被拒绝（换行能拼出多余记录并绕过标题查重），多行内容压成一句或改成并列短语。

`add`、`promote`、`replace` 都会做结构校验，格式不合法的记录不会写入，避免 `recall` 静默忽略它。旧五字段（`date`/`scene`/`cause`/`evidence`/`fix`）只读兼容：`add` 与 `promote` 会明确拒绝旧格式或旧参数，并提示先 `inspect` 查看、再用 `replace` 整份迁移到新格式；不要指望写入入口自动改写旧记录，也不允许静默丢弃。

命令输出是 JSON，包含路径、容量和版本，便于脚本与维护使用；`promote` 会同时给出目标与候选两份文件的 `version`。`--dry-run` 在 `add`、`promote`、`replace` 上都只做同样的校验与容量展示，不写盘。写入使用同目录临时文件加原子替换，读-改-写在短时 flock 锁内完成，目录被占用时报 `BUSY`；被拒绝时原文件内容不变。需要人工确认写入安全时，`--expect` 版本比对不符会报 `STALE_VERSION`。

路径参数说明：`--project` 给的是默认位置的基准目录（默认当前工作目录），脚本不会去探测 Git 根；需要指向别处时显式给出 `--project-path` 与 `--global-path`。`--project-path` 语义是**文件路径**，若传进来的是已存在的目录，会按该目录下的 `gotchas.md` 处理。这些覆盖参数只用于测试或特殊工作区，不能用来绕开容量上限。

## 容量上限

三份文件（全局、项目、候选）各有 **4000 个 Unicode 码点**的硬上限，标题、字段名、标点与换行都计入；CRLF 算两个码点。计数按码点而不是字节，也不做空白规范化，所以中文与 emoji 都按实际字符数算。

上限是固定常量，没有调高它的命令开关。文件超限时 `add` 与 `promote` 都会拒绝继续积累，必须先用 `replace` 把文件改到 4000 以内。此时不会静默截断、清空或删除任何原有内容。`promote` 写入两份文件（目标追加、候选移除），两者不在同一个事务里：如果第二份写入失败，可能只有目标生效。脚本会在原子替换后立即报告结果与版本，遇到异常先 `inspect` 确认两份文件的实际状态，再决定是否重试。

## 维护：先提方案，再提交

维护是显式动作，入口是 `inspect`：

```bash
python3 ~/.agents/skills/capture-gotcha/scripts/add_gotcha.py inspect --scope global
python3 ~/.agents/skills/capture-gotcha/scripts/add_gotcha.py inspect --scope project
python3 ~/.agents/skills/capture-gotcha/scripts/add_gotcha.py inspect --scope candidate
```

不带 `--scope` 时三份都显示。它只读，输出文件路径、是否存在、字符数与上限、是否超限、用于防覆盖的 `version`、结构状态、记录条数和完整正文；文件不存在时给出明确状态。结构状态分四种：`ok`；`legacy`（旧五字段，可读、建议迁移）；`readable`（`recall` 会原样输出，但写入前需先用 `replace` 修正，例如「验证」没写日期）；`invalid`（读不出，整份都不作为记忆输出）。任一文件读不出时只影响它自己，另两份照常显示。`inspect` 是唯一允许查看超限文件正文的入口。

精简、合并或删除记录时，先把具体方案（保留哪些、删掉哪些、合并成什么样）说给用户，得到同意后提交；不要自动删除，也不要按文件年龄淘汰记录。提交用整份修订稿：

```bash
python3 ~/.agents/skills/capture-gotcha/scripts/add_gotcha.py replace \
  --scope global --from-file /path/to/修订稿.md --expect <inspect 的 version>
```

`replace` 用于修改、合并或清空记录，也是修复超限文件和把旧五字段迁到新格式的唯一方式。它先校验修订稿的容量和结构，再在锁内比对 `--expect` 与文件当前版本，一致才写入；版本不符（`STALE_VERSION`）说明期间有人改过文件，重新 `inspect` 后基于最新正文再合并。允许写成一个只有 `# Gotchas` 的空文件来清空记录，这算成功而不是读取失败。迁移旧记录时保持各自的证据与时间，不得无依据地机械改写。

去重规则保持简单：新标题与已有记录标题互为子串即跳过。它只看标题，不做语义检索，因此标题写得越具体，这条规则越有用；也确实可能漏掉换了说法但内容重复的记录，需要人工判断。跳过时命令会返回 `skipped` 与命中的已有标题，不会静默吞掉你新写的内容——确认这是条新规则时，换个更具体的标题重写一次。

## 自检

先语法核验，再把自检放在会话临时目录里跑，不要触碰真实记忆：

```bash
python3 -B skills/capture-gotcha/scripts/add_gotcha.py self-test --scratch "$PI_SCRATCH_DIR"
```

自检用虚构数据覆盖容量边界（4000 可写、4001 拒绝，含 CRLF）、三个作用域的超限保护、旧超限文件与旧五字段文件的 inspect/recall/replace、版本冲突、格式不合法、候选不召回、转正容量不足不丢候选、dry-run 不写盘、失败时原文件不变、关键词匹配与项目在先的顺序、原子替换与锁的基本行为，以及字段含换行的注入、BOM 文件、单份文件非 UTF-8 时的降级、`--project-path` 传目录的语义。它不会读写 `~/.agents/gotchas.md`，跑完不留临时文件与 `__pycache__`（锁文件按 flock 语义保留）。

## 已知限制

这些是刻意的取舍或尚未处理的边界，动手前先看一眼：

- **单份文件读不出会丢掉它全部内容**：标记为 `invalid` 的文件整份不输出。一份文件里只要有一条记录格式不对，`recall` 也不会输出该文件里其它完好的记录——这是「不静默忽略」的代价。写入入口（`add`/`promote`）同样拒绝在结构不合法或超限的文件上继续积累。
- **非 UTF-8 只能手工修**：文件存成 UTF-16 等编码时，`inspect` 给出该文件的状态但不显示正文，`replace` 也会拒绝（它要先能解码当前内容才能比对版本）。先用编辑器或 `iconv` 转成 UTF-8，再走 `replace`。
- **BOM 会被剥掉**：文件开头若有 UTF-8 BOM，读取时忽略，写回时不再带 BOM，容量按剥离后的文本计。
- **锁文件常驻**：`.capture-gotcha.lock` 是 `flock` 用的 0 字节文件，加锁后保留是正常现象，不要删。它会让「记忆目录」在首次写入后一直存在，即使在项目里只做过一次注定失败的写入。
- **`promote` 不是事务**：两份文件分两步写，第二步失败会报 `PARTIAL` 并给出目标的新版本；此时先 `inspect` 确认两份的实际状态再决定是否手工清理候选。
- **去重只看标题**：不比对正文，换了说法但内容重复的记录会漏判。
- **依赖 POSIX**：脚本在模块顶层 `import fcntl`，只支持 Linux/macOS，没有 Windows 兜底。
- **不核验事实也不保证脱敏**：脚本只管格式、容量与写入安全；证据是否成立、凭证是否已去掉，都由写的人负责。
