# Capture Gotcha

## 触发与顺序

涉及项目、终端、浏览器、MCP、文件、构建、测试、部署或工具调用的任务，开始先执行 `recall`，按项目记忆 → 全局记忆读取正式经验；候选不参与。任务看起来简单也不跳过，不要凭记忆猜文件或命令的位置。读完确认命中规则、项目是否覆盖全局（冲突时项目优先）、命令与路径是否需要调整，再动手。

出错时用错误码、模块名或现象作关键词回查，可给多个词，同一范围内命中多的排在前面（项目仍在全局之前）；全不命中会列出可用标题，换更贴近的词再查。

`recall` 非零退出表示有文件读不出、超限或跳过了坏记录，不代表调用失败：先看它打印的原因，能读的记录已经输出；需要修再停下。

修复后按下一节判断范围并写回，完成沉淀。同类问题不再重复摸索，这是本技能的唯一目的。

```bash
python3 <脚本> recall
python3 <脚本> recall '错误码' '模块'
```

## 范围

- **项目记忆** `<项目根>/.agents/gotchas.md`：当前代码、配置、目录结构、业务约定、项目工具链特有。
- **全局记忆** 默认 `~/.agents/gotchas.md`：离开当前项目仍成立的本机环境、通用工具、权限、代理、shell 与包装层行为。
- **候选记忆** `<项目根>/.agents/gotchas-candidates.md`：范围或结论未定，先写这里，不参与 `recall`；确认后用 `promote '关键词' --scope project|global` 转正。转正要补足真实证据，不是只把内容挪个位置。

判别句：换到完全无关的项目，这条经验还成立吗？是→全局；否→项目。服务某个项目的素材站点一律算项目；只把工具本身的跨项目行为写全局。项目特例不得污染全局，拿不准先写候选。

## 写入

写前先用拟记录的关键词跑 `recall '词1' '词2'`，再 `inspect` 看已有标题；已有同义记录用 `edit` 改，不新增。确实新规则才 `add`；同标题 `add` 会返回 `skipped` 与命中的标题，要改内容用 `edit`，不要换个标题硬塞第二条。

每条格式固定：

```text
### 规则名（写可迁移的动作，不写事故）
- 适用: 什么情况下会遇到，一句话
- 做法: 怎么改，一到两句
- 关键词: 2–5 个检索词，空格分隔
```

只记「什么错 + 怎么改」，有真实证据才写；证据留在事故记录里，不落盘成字段。字段值必须单行，换行与 U+2028 等行分隔符会被拒绝。关键词写别人会查的词：错误码、工具名、症状、模块名。值不值得收与怎么提炼见 [references/refining.md](references/refining.md)。

内容纪律：适用 ≤50 字、做法 ≤120 字、关键词 ≤40 字、单条 ≤300 字。写不下说明该拆，或根本不该收。临时进度、泛泛建议和一次性偶发故障都不收；写前删掉凭证，脚本只做有限遮挡。

```bash
python3 <脚本> add --scope project --title '规则名' \
  --when '触发条件' --action '可执行动作' --keywords '词1 词2'
```

也可用 `--from-entry <片段|->` 提交一条完整记录。旧五字段与带「验证」的旧三字段仍可读、照常召回，不强制迁移；新增记录只接受新格式，迁移用 `edit --from-entry` 或 `replace`。

## 维护

- `inspect --scope global|project|candidate`：只读，看路径、容量、版本、结构状态与正文；不带 `--scope` 看三份。超限时它是唯一能看正文的入口。结构状态为 `ok`/`legacy`/`readable`/`partial`/`invalid`：`legacy` 仍可召回，`partial` 只输出可读记录，`invalid` 整份不输出。
- `edit '<标题>' --scope ... --expect <version>`：只改命中一条；可给 `--when`/`--action`/`--keywords`，或用 `--from-entry` 整条替换。
- `drop '<标题>' --scope ... --expect <version>`：删一条；失效规则用 `drop` 删掉、不留归档，需要时从 git 历史回溯。
- `replace --scope ... --from-file <修订稿> --expect <version>`：整份提交，用于合并、重排、清空和迁移旧格式；可以提交只有 `# Gotchas` 的空文件来清空。

每次改前先 `inspect` 取最新 `version`，`--expect` 用它；版本不符报 `STALE_VERSION`，重新看正文再合并。单条维护只动命中记录，其余字节不变；标题找不到会列出相近标题。

写命令返回 `near_limit`；达到 85% 时主动向用户提出合并或精简方案，同意后再改。方案说清保留哪些、删掉哪些、合并成什么样。永不自动删除，也不按文件年龄淘汰；文件里只留仍有效的规则。

## 跨 harness

`<脚本>` 指实际安装的 `capture-gotcha/scripts/add_gotcha.py`，不同 harness 的加载目录不同，不照搬示例路径；有 `python3` 用 `python3`，没有就用 `python`。

全局记忆默认 `~/.agents/gotchas.md`，设置 `GOTCHA_HOME` 可重定向全局目录；项目记忆从当前目录向上找最近的 `.agents/gotchas.md`（跳过全局记忆文件自身，避免两个作用域变成同一份），没有则回退 Git 根或当前目录。`--project-path` 与 `--global-path` 只用于测试或特殊工作区，不能绕开容量上限。

容量口径、写入安全、结构状态、逐条打捞、已知限制与自检命令见 [references/maintenance.md](references/maintenance.md)。
