# Capture Gotcha

把已验证的经验变成下一次任务开始时可直接执行的规则。价值在于稳定召回，所以相关任务都遵循固定顺序：**recall → 执行 → 按错误查询 → 修复验证 → 沉淀**。

记什么、写到哪个范围由 AI 按下面的规则判断；脚本只保障容量、版本与写入安全，不核实事实，也不保证脱敏完备。

## 开始任务：强制 recall

只要任务涉及项目、终端、浏览器、MCP、文件系统、构建、测试、部署或工具调用，先运行：

```bash
python3 ~/.agents/skills/capture-gotcha/scripts/add_gotcha.py recall
```

不要凭记忆猜文件位置，也不要因为任务看起来简单而跳过。无关键词 `recall` 按项目记忆、全局记忆的顺序输出正式经验；候选记忆不输出。

读完后检查三件事：

1. 当前任务是否命中某条规则。
2. 项目经验是否覆盖全局经验；冲突时遵守项目经验。
3. 是否有记忆中的命令、路径或工具限制需要在动手前调整。

遇到具体错误时，再用关键词查询。可以一次给多个词，命中词数多的排前面（`.lower()` 逐词做子串匹配，不是语义检索）：

```bash
python3 ~/.agents/skills/capture-gotcha/scripts/add_gotcha.py recall '错误码' '涉及的模块'
```

关键词全不命中时，它会列出全部可用记录的标题——照标题换个更贴近的词再查一次，比凭空猜词可靠。

## 判断记忆范围

正式记忆两处，候选一处：

- **项目记忆**：`<项目根>/.agents/gotchas.md`。当前代码、配置、目录结构、业务约定或项目工具链特有的经验写这里。
- **全局记忆**：`~/.agents/gotchas.md`。脱离当前项目仍成立的本机环境、通用工具行为、权限、代理、路径、shell 和包装层经验才写这里。
- **候选记忆**：`<项目根>/.agents/gotchas-candidates.md`。范围或结论还没确认时先写这里，不参与 `recall`。

问自己：换到一个完全无关的项目，这条经验是否仍然成立？是，才考虑全局；否，写项目。项目特例绝不能污染全局。无法判断范围时，先写项目候选，验证后再提升。

## 写入

```bash
python3 ~/.agents/skills/capture-gotcha/scripts/add_gotcha.py add \
  --scope project --title '可迁移的规则名' --when '触发条件与适用边界' \
  --action '可执行动作；根因仅在影响动作时补一句' \
  --verified '2026-01-01 最短验证依据'
```

记录格式固定为 `# Gotchas` 加每条 `### 标题` 与其后的 `适用`、`做法`、`验证` 三个字段；`--verified` 省略时只写入当天日期，最好补上最短验证依据。字段名用半角冒号，全角冒号也接受（中文输入法正常写法不会丢数据）。`验证` 必须以 `YYYY-MM-DD` 日期开头。

三个字段值都必须是**单行**：含换行会被拒绝（换行能拼出多余记录并绕过标题查重），多行内容压成一句或改成并列短语。

**写正式记录前先读 [`references/refining.md`](references/refining.md)**——那里有入库门槛（值不值得收、什么不收）和把一次事故提炼成可迁移规则的完整规则，以及候选写法。

## 维护：先提方案，再提交

维护是显式动作，入口是 `inspect`：

```bash
python3 ~/.agents/skills/capture-gotcha/scripts/add_gotcha.py inspect --scope global
python3 ~/.agents/skills/capture-gotcha/scripts/add_gotcha.py inspect --scope project
python3 ~/.agents/skills/capture-gotcha/scripts/add_gotcha.py inspect --scope candidate
```

不带 `--scope` 时三份都显示。它只读，输出路径、是否存在、字符数与上限、是否超限、用于防覆盖的 `version`、结构状态、记录条数和完整正文；文件不存在时给出明确状态。结构状态五种：`ok`；`legacy`（旧五字段，可读、建议迁移）；`readable`（`recall` 会原样输出，但写入前需先用 `replace` 修正，例如「验证」没写日期）；`partial`（部分记录读不出，`recall` 输出可读的那些并逐条报出跳过的）；`invalid`（整份读不出，不作为记忆输出）。任一文件读不出只影响它自己，另两份照常显示。**`inspect` 是唯一允许查看超限文件正文的入口。**

精简、合并或删除记录时，先把具体方案（保留哪些、删掉哪些、合并成什么样）说给用户，得到同意后提交。**不要自动删除，也不要按文件年龄淘汰记录；不得借「要满容量了」静默删除，也不得无限归档或私自改上限**——保留仍有效的边界与证据时间。提交用整份修订稿：

```bash
python3 ~/.agents/skills/capture-gotcha/scripts/add_gotcha.py replace \
  --scope global --from-file /path/to/修订稿.md --expect <inspect 的 version>
```

`replace` 用于修改、合并或清空记录，也是修复超限文件和把旧五字段迁到新格式的唯一方式。它先校验修订稿的容量和结构，再在锁内比对 `--expect` 与文件当前版本，一致才写入；版本不符（`STALE_VERSION`）说明期间有人改过文件，重新 `inspect` 后基于最新正文再合并。允许写成一个只有 `# Gotchas` 的空文件来清空记录，这算成功而不是读取失败。迁移旧记录时保持各自的证据与时间，不得无依据地机械改写。

去重规则保持简单：新标题与已有记录标题互为子串即跳过。它只看标题，不做语义检索，因此标题写得越具体越有用；也确实可能漏掉换了说法但内容重复的记录，需要人工判断。跳过时命令会返回 `skipped` 与命中的已有标题，不会静默吞掉你新写的内容——确认这是条新规则时，换个更具体的标题重写一次。

## 容量与写入安全

三份文件各有 **4000 个 Unicode 码点**的硬上限，标题、字段名、标点与换行都计入；CRLF 算两个码点。计数按码点而不是字节，不做空白规范化，中文与 emoji 按实际字符数算。上限是固定常量，没有调高它的开关。

文件超限时 `add` 与 `promote` 都拒绝继续积累，必须先 `replace` 改到 4000 以内；不会静默截断、清空或删除任何原有内容。`recall` 遇到超限文件时，明确报告路径与字符数并以非零退出，**不把超限文件截断后当作正常记忆输出**；此时先按「维护」一节修复再继续任务。格式坏掉的记录则逐条打捞：能读的照常输出，坏掉的报出标题与原因并跳过，**不让一条坏记录连坐同文件其余完好的记录**。判「坏」的尺度与写入侧一致：标题行必须严格是 `### 标题`（缩进、缺空格、多一个 `#` 都算坏），字段必须正好是 `适用`/`做法`/`验证`。不属于任何记录的散落内容同样报出。记录边界是 Markdown 水平线：一行只由 3 个及以上 `-`/`*`/`_` 与空白组成（如 `---`）才算边界，它之后到下一个 `### 标题` 之前的内容即散落内容，会被报出但不作为记忆输出；必须整行如此，同行还有其他内容（`--- 同行尾注`）或以 `- ` 开头的正文行都不算边界。写入入口仍按整份严格校验拒绝，坏文件上不允许继续积累。

只要 `recall` 报告了任何问题（文件级失败、超限，或跳过了坏记录），它就以非零退出——**退出码非零表示「有需要修的东西」**，不表示这次调用失败：能读的记录都已正常输出。看到非零退出先读它打印的原因，再决定是否停下修复。

`add`、`promote`、`replace` 都做结构校验，格式不合法的记录不会写入，避免 `recall` 静默忽略它。旧五字段（`date`/`scene`/`cause`/`evidence`/`fix`）只读兼容：`add` 与 `promote` 明确拒绝旧格式并提示先用 `replace` 整份迁移，不静默丢弃。

写入用同目录临时文件加原子替换，读-改-写在短时 flock 锁内完成，目录被占用时报 `BUSY`；被拒绝时原文件内容不变。命令输出是 JSON，含路径、容量和版本（`promote` 同时给出目标与候选两份的 `version`）；`--dry-run` 在三个写入命令上都只做校验与容量展示，不写盘。`replace` 的 `--expect` 与当前版本不符时报 `STALE_VERSION`。

路径参数：`--project` 给的是默认位置的基准目录（默认当前工作目录），脚本不探测 Git 根；需要指向别处时显式给 `--project-path` 与 `--global-path`。`--project-path` 语义是**文件路径**，传进来的是已存在目录时按该目录下的 `gotchas.md` 处理。这些覆盖参数只用于测试或特殊工作区，不能用来绕开容量上限。

## 自检

改过脚本或记忆结构后跑一次。先语法核验，再把自检放在会话临时目录里跑，不要触碰真实记忆：

```bash
python3 -B skills/capture-gotcha/scripts/add_gotcha.py self-test --scratch "$PI_SCRATCH_DIR"
```

用虚构数据覆盖共 41 项：容量边界（4000 可写、4001 拒绝，含 CRLF）、三作用域超限保护、旧超限与旧五字段文件的 inspect/recall/replace、版本冲突、格式非法、候选不召回、转正容量不足不丢候选、dry-run 不写盘、失败时原文件不变、关键词匹配与项目在先的顺序、原子替换与锁、字段换行注入、BOM、单份文件非 UTF-8 的降级、逐条打捞（单条坏不连坐、多条各自报出、标题不合法与散落内容都报出、全坏退化为 invalid 且仍给出正文）、水平线整行匹配（`--- 同行尾注`、`- **加粗** 说明` 同行还有内容都不算边界，`-`/`*`/`_` 三种都算、`--` 两个不算）、缩进标题诊断报出保留行首缩进的原文并点明症状（U+3000/U+00A0 等前导空白同样算缩进，两个症状独立给出）、缺头行文件的 entries 带上 `###` 标题行数提示、`READ_ERROR` 与解码失败分文案、多关键词按命中数重排、不命中时列出标题、`--project-path` 传目录的语义。不读写 `~/.agents/gotchas.md`，跑完不留临时文件与 `__pycache__`（锁文件按 flock 语义保留）。

## 已知限制

刻意的取舍或尚未处理的边界，动手前先看一眼：

- **非 UTF-8、没有头行、或读不出（权限/路径）的文件仍会整份丢**：这几类没法逐条打捞——编码读不出时无从解析，没有 `# Gotchas` 头行时无法可靠区分记录与散落文本，读错误（如权限不足、路径是目录）时拿不到内容，所以 `recall` 整份不输出并报明原因（读错误报 `READ_ERROR`）。`inspect` 对读不出与解码失败给不同文案：读不出时报「文件读不出：路径类型、权限等原因」、条数为「未知」，只有真编码错误（UTF-16 等）才报「无法按 UTF-8 解码」，不把权限/目录问题说成 0 字节或解码失败。这类失败只影响那一份文件，其余作用域照常输出。逐条打捞只覆盖「头行正常、个别记录格式坏」的情况：那几条被跳过并逐条报出，同文件其余记录照常召回。`inspect` 对能解码的文件始终给出真实容量、条数与正文（即使结构 invalid），它是唯一能看正文的维护入口——先看原文再用 `replace` 修，不要因为状态不是 `ok` 就当成空文件覆盖。
- **非 UTF-8 只能手工修**：存成 UTF-16 等编码时，`inspect` 给出状态但不显示正文，`replace` 也拒绝。先用编辑器或 `iconv` 转成 UTF-8 再走 `replace`。
- **BOM 会被剥掉**：文件开头有 UTF-8 BOM 时读取忽略，写回不再带 BOM，容量按剥离后的文本计。
- **锁文件常驻**：`.capture-gotcha.lock` 是 `flock` 用的 0 字节文件，加锁后保留属正常，不要删。它会让记忆目录在首次写入后一直存在，即使在项目里只做过一次注定失败的写入。
- **`promote` 不是事务**：两份文件分两步写，第二步失败报 `PARTIAL` 并给出目标的新版本；此时先 `inspect` 确认两份实际状态再决定是否手工清理候选。目标容量不足或候选不唯一时整体拒绝，候选保留不丢。
- **去重只看标题**：不比对正文，换了说法但内容重复的会漏判。
- **依赖 POSIX**：脚本在模块顶层 `import fcntl`，只支持 Linux/macOS，无 Windows 兜底。
- **不核验事实也不保证脱敏**：脚本只管格式、容量与写入安全；证据是否成立、凭证是否已去掉，由写的人负责。
