# 维护与容量

维护记忆文件、排查容量或改动脚本时读这一份。日常写入与召回规则见 [SKILL.md](../SKILL.md)。

## 容量

- 三份文件（全局 / 项目 / 候选）各有 **4000 个 Unicode 码点**硬上限，是固定常量，没有调高开关。
- 计数用 `len(text)`：标题、`###`、字段名、冒号、空格和换行都算；CRLF 算两个码点；不做空白规范化；中文和 emoji 按实际字符数算。读入时剥掉开头的 UTF-8 BOM，容量按剥离后的文本计。
- 单字段还有脚本硬上限：`适用` 120、`做法` 240、`关键词` 80 字符。技能里的内容纪律更严（50 / 120 / 40，单条 300 字），按纪律写。
- 文件超限时 `add` 与 `promote` 拒绝继续积累；`recall` 不输出超限文件，报告路径与字符数并以非零退出；`inspect` 仍给出真实容量和正文，是查看超限文件的唯一入口。用 `replace` 改到 4000 以内。
- `near_limit` 表示 `characters_after` 达到上限的 85%（3400 码点起为 `true`）。`add`、`promote`、`edit`、`drop`、`replace` 都输出该布尔值；为 `true` 时主动向用户提合并或精简方案。

## 写入安全

- 读-改-写在短时目录锁内完成。锁文件是记忆目录下的 `.capture-gotcha.lock`；POSIX 用 `fcntl`，Windows 用 `msvcrt`，都没有时降级为不加锁并在写命令输出 `lock: none` 与说明。拿不到锁报 `BUSY`，重试仍失败就稍后再做，不要删锁文件。
- 写入用同目录临时文件加 `fsync`，再以 `os.replace` 原子替换；失败时原文件内容不变，不会静默截断。
- 版本是文件字节的 SHA-256。`inspect` 输出的 `version:` 用于 `edit`、`drop`、`replace` 的 `--expect`；不一致报 `STALE_VERSION`，重新 `inspect` 取最新正文后合并。`add` 与 `promote` 不做显式版本参数，也在同一把锁内读-改-写。
- `--dry-run` 在 `add`、`promote`、`edit`、`drop`、`replace` 上只做校验与容量展示，不写盘。
- `edit` 只替换命中的那一条，其余字节不变；可给 `--when`/`--action`/`--keywords`，或用 `--from-entry` 整条替换；改名撞上已有标题报 `DUPLICATE`。`drop` 只删命中的那一条。两者找不到标题都报 `NOT_FOUND` 并列出相近标题。
- 标题去重只比较标题本身：忽略大小写与首尾空白，完全相同才跳过。`add` 跳过时返回 `skipped`、`matched` 与命中的标题；同义不同写法需人工判断，改已有记录用 `edit`。

## 结构状态

`inspect` 的 `structure:` 有五种：

- `ok`：结构与字段都符合现行格式。
- `legacy`：旧五字段或带「验证」的旧三字段。仍可读、照常召回；可继续追加或维护新格式记录，但旧格式输入仍会被拒绝。需要迁移旧记录时用 `edit --from-entry` 单条改，或用 `replace` 整份改；不强制立即迁移。
- `readable`：`recall` 会原样输出，但写入前需用 `replace`（或 `edit`）修正；例如字段超过硬上限等「能读但写入会拒绝」的状态。
- `partial`：部分记录读不出。`recall` 输出可读记录，并逐条报出跳过的记录与散落内容。
- `invalid`：整份不作为记忆输出（无头行、全部记录读不出、编码错误等）。能解码时 `inspect` 仍显示原文，先看原文再修，不要当成空文件覆盖。

## 逐条打捞

- 文件有 `# Gotchas` 头行且能按 UTF-8 解码时，`recall` 逐条解析；某条坏了只跳过并报出标题与原因，同文件其余记录照常输出，不让一条坏记录连坐整份文件。
- 标题必须顶格且严格为 `### 标题`；缩进、缺空格、多一个 `#` 都算坏记录。现行记录的字段必须正好是 `适用`、`做法`、`关键词`；旧五字段与旧三字段可读但标 `legacy`。
- Markdown 水平线（整行只由 3 个及以上 `-`/`*`/`_` 与空白组成）是记录边界；它之后到下一个标题之前的内容算散落内容，会报出但不作为记忆输出，也不并进上一条记录。
- `recall` 报告任何问题（文件读不出、超限、跳过坏记录或散落内容）都会以非零退出。这表示「有需要修的东西」，不是调用失败；能读的记录已经输出。
- `inspect` 是唯一能查看超限或坏文件正文的维护入口；先看原文，再用 `replace` 整份修。

## 已知限制

- **非 UTF-8、缺少 `# Gotchas` 头行、读不出（权限/路径）的文件仍整份丢**：这三类无法逐条打捞——编码读不出时无从解析，没有头行时无法区分记录与散落文本，读错误时拿不到内容。`recall` 整份不输出并报明原因；需要先转成 UTF-8 或补头行，再用 `replace` 修。
- **BOM 会被剥掉**：读取时忽略开头 UTF-8 BOM，写回不再带 BOM；容量按剥离后的文本计。
- **锁文件常驻**：`.capture-gotcha.lock` 是锁用的文件（POSIX 下通常为 0 字节，Windows 下需写入 1 字节区间），加锁后保留属正常，不要删。首次写入也会让记忆目录一直存在。
- **`promote` 不是事务**：两份文件分两步写，第二步失败报 `PARTIAL` 并给出目标的新版本；此时先 `inspect` 两份确认实际状态，再决定是否手工清理候选。目标容量不足或候选不唯一时整体拒绝，候选保留。
- **Windows 锁未在真机验证**：只在代码里做了 fcntl/msvcrt 条件导入与两者都缺失时的无锁降级，Windows 行为未经实机验证；跨平台使用前先跑自检，失败时按实际报错处理。
- **去重只看标题**：不比对正文，换了说法但内容重复的记录会漏判。
- **不核验事实**：脚本只管格式、容量与写入安全；证据是否成立由写入者负责，凭证不要写进记录（脚本只有有限的遮挡规则，不保证脱敏完备）。

## 路径

- 全局记忆默认 `~/.agents/gotchas.md`；设置 `GOTCHA_HOME` 可把它重定向到 `$GOTCHA_HOME/gotchas.md`，空串或相对路径会回退默认并给出说明。
- 项目记忆从探测起点向上找最近的 `.agents/gotchas.md`；找不到再找 Git 根，最后回退起点，起点默认当前工作目录，可用 `--project` 指定。
- `--project-path`、`--global-path` 是测试或特殊工作区的覆盖参数，不能用来绕开容量上限；`--project-path` 传已存在目录时按该目录下的 `gotchas.md` 处理。

## 自检

改过脚本或记忆结构后跑一次，只在会话临时目录用虚构数据自检，不写入真实记忆：

```bash
python3 -B skills/capture-gotcha/scripts/add_gotcha.py self-test --scratch "$PI_SCRATCH_DIR"
```

覆盖容量边界与超限保护、字段上限、行分隔符拒绝、`edit`/`drop` 的整条替换与删除、版本冲突、改名重复、`near_limit` 的 85% 边界、逐条打捞、BOM、非 UTF-8 降级、原子替换与锁等。跑完临时目录删除，不产生 `__pycache__`；锁文件按锁语义保留属正常。
