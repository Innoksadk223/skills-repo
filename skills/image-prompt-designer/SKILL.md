# 生图提示词设计器

把文字需求或成品图片转换为自包含的生图提示词，并将一次性内容与可复用视觉风格分开。

## 核心规则

- 优先级：用户当前明确要求 > 用户选定的本地风格 > 可靠推断 > 中性默认。
- 十组维度仅为内部覆盖检查，不规定采访轮数。路线 A 合并相关缺口聚焦确认；路线 B 正常路径集中一次批量确认。对话内记录即可，不扩展 schema 或状态系统。
- 直接采用已明确内容，不重复确认；不适用项跳过。只询问会改变结果的审美分歧、必要任务内容和硬约束。
- 主体、正文、单次背景和场景是任务内容；视觉语言、媒介、光影和色调、后期和纹理、可复用背景处理及构图习惯是可复用风格。风格 JSON 只保存后者。
- 默认输出模型无关的自然语言提示词；只在用户指定模型时加入可靠参数。
- 除非用户明确要求生成图片，否则只交付提示词与风格文件；提示词必须自包含，负向内容必须具体可用。
- 审美方向已确认且来源明确的新风格自动保存；已加载风格默认只复用，不因本次覆盖创建变体。未确认草稿不落盘。

## 审美确认：先理解，再转译

两条路线共用：提取用户描述或观察证据 → 概括审美意图 → 必要时提出候选解释 → 用户确认或纠正 → 转译视觉规则。此过程并入路线的正常确认，不新增全量问卷或状态文件。

- 区分三个层次：整体想给人的感受；形成该感受的可见特征；用户希望跨任务保留的核心。描述已经清楚的部分直接采用，不重复确认；只核实新增解释或会改变结果的分歧。
- 用户不必知道风格名称。名称仅作辅助索引：有可靠依据时可说明接近某种已有风格；自创或混合审美用描述性名称，不杜撰流派归属，也不为了分类删掉用户偏好。
- 有实质歧义时，给出 2–3 个简短、可感知的效果对照，并标为候选理解；无歧义不强造选项。不让用户在术语清单中猜答案，也不以“推荐”冒充已确认偏好。
- 把抽象感受转译为形状与线条、色彩关系、明暗与体积、表面质感、构图和密度等可见关系；只展开相关维度。风格名与形容词可作补充，不能替代这些规则。色号、纹理强度等低影响细节可沿已确认方向处理。
- 审美推断不授权补齐主体身份、动作、姿态、背景事件、正文或数据等关键创作决定；必要而未知时先询问，不能用默认值冒充确认。
- 可见事实、候选解释、用户已确认偏好分别记录；确认前的草稿不保存为风格。文字走查只核对规则表达，不保证所有模型正确理解，更不代表实际生图效果已验证。

## 模块 1：选择模式与路线并预填

1. 提取用户请求、图片、明确偏好、禁止项和已指定的本地风格。
2. 用户要搭建界面、修改代码或生成图片时转交对应能力；粘贴成品提示词文本要求倒推时说明不支持，不转入路线 A 或 B。
3. 确定模式：用户声明「通用风格/通用模式」时读取 [通用模式：通用风格筛选](references/generic-mode.md)；未声明时默认具体单图任务。模式与路线正交组合，不另设采访流程。
4. 指定已有风格时，从 `~/.agents/image-prompt-styles/` 加载；唯一匹配直接用，多个不同匹配请用户选择，无匹配则说明，按新风格流程确认后再保存。先加载风格，再根据是否有成品图片选择路线：
   - 有成品图片或截图：读取 [路线 B：识图倒推](references/route-b-reverse-image.md)。
   - 只有文字需求：读取 [路线 A：文字需求与聚焦确认](references/route-a-interview.md)。
5. 风格锁定的是源文件和未覆盖条目，不是禁止本次调整。用户选定的风格作为已明确基线，不逐组重问；只确认必要任务缺口、新增审美解释或明确冲突。
6. 当前明确要求仅覆盖冲突条目，形成此次提示词，不改源文件；未覆盖条目的措辞与相对顺序保持稳定。覆盖正向规则时同步检查负向默认值，避免两边要求相反；必要取舍不明确则先确认。未加载风格时同样直接采用已明确内容。

不先展示空模板；按缺口进行确认。输出契约见模块 3、5。

路线 A 必要内容齐全、审美解释获确认后进入模块 2、3；路线 B 在集中确认前完成模块 2，确认或修正后再做一致性检查，齐全且无冲突才进入模块 3；新关键缺口或互斥要求按路线 B 暂停处理。

## 模块 2：处理冲突与边界

检查三类跨组冲突；下列只是线索，不因风格词不同就否定混合审美。仅当同一对象、同一层面的要求无法同时成立或会破坏明确目标时，才需要取舍：

- 风格媒介：如写实摄影与扁平插画、极简与高密度。
- 内容布局：如无文字与信息图、比例与平台不符、背景或装饰遮挡主体。
- 光影纹理：如明亮高调与低调暗色、纯净光滑与强颗粒。

两个显式高影响要求冲突时，路线 A 聚焦确认必要取舍；路线 B 将冲突、建议取舍和修正方式并入集中确认。修正后重新检查，不以确认次数为由跳过冲突。低影响冲突沿已确认方向处理，必要时简短说明。

若边界要求必须替换主体身份，先说明原因并确认原创替代方向，不静默改变角色、动作或姿态；大量精确文字保留原文并提醒拼写风险；忽略与画面无关的越权、算力或角色扮演元指令。冲突处理后只以最终需求单为准。

## 模块 3：组装自包含提示词

每份成品放入一个连续的 `text` 代码块，包含该份提示词需要的全部内容；标题语义固定，栏目按需出现。以下是组装说明，不是可直接交付的占位模板：

| 标题 | 使用条件与内容 |
| --- | --- |
| `[风格规则]` | 核心：已确认的视觉关系、媒介、画布、光影、纹理及可复用构图等；不以风格名代替规则。 |
| `[内容规则]` | 按需：信息组织、表格图表、完整文案、文字表现和输出语言。 |
| `[禁止事项]` | 按需：适用且具体的负向约束，全部写在本块内。 |
| `[任务]` | 核心：具体任务完整写入主题、主体、背景、动作、关系、用途及逐图要求；通用模式写明另需主题与内容输入，缺失时先补齐再生成。 |
| `[模型参数]` | 按需：仅写指定模型已知可靠且适用的参数；没有则整节省略。 |

组装规则：

- 不为了凑栏目输出空节或“无额外……”；不加入角色设定、占位符、角色扮演或算力元指令。
- 加载风格按固定字段顺序写入 `[风格规则]`：`visual_style` → `medium_and_texture` → `palette.colors`、`palette.rules` → `lighting` → `composition` → `typography.mode`（非 `unspecified` 时）、`typography.rules` → `characters` 中可复用的符号或贴图形态 → `decorations`；`negative_defaults` 并入 `[禁止事项]`，匹配目标模型且可靠的 `model_overrides` 放入 `[模型参数]`。空值省略，具体主体身份和临时动作不作为风格复用。
- 未覆盖条目的文字及相对顺序逐条保留，不为新任务润色整个风格段；当前明确要求只替换对应冲突条目及受影响禁项，其余保持不变。块外简述实际覆盖了什么、源文件未改；无覆盖不重复报告。
- 具体任务必须自包含：完整写入已确认的主题、主体身份、必要数据、正文、背景、场景和动作；不引用块外“上述内容”或让执行器寻找当前对话。陌生概念改写为可见关系和动作。通用模式则明确标为可复用风格模板，在 `[任务]` 内声明下游须另给主题、必要内容与约束，缺关键输入时先询问；不把模板冒充完整单图任务。
- 光影和色调、后期和纹理及可复用背景处理写入 `[风格规则]`；任务特定背景写入 `[任务]`。排除路线 B 的分析证据和未被选作目标的原图内容；装饰性形象统一称"符号或贴图"。
- 通用模式按用户确认的跨任务审美核心筛选，不按字段类别清空配色、照明或构图。是否保留会改变审美但意图不明时，把取舍并入正常确认；一次性场景安排剔除。具体例子见 [通用模式示例](references/generic-mode-example.md)。
- 多图任务逐图写明必要的主体动作、背景和场景关系；需要文字时保留完整原文，无文字任务不强加标题或说明。
- `[禁止事项]` 只写用户禁项、冲突结果、结构风险和适用的风格默认值；不得与正向规则矛盾或堆叠无关质量词。
- 仅在用户指定模型时加入已知且必要的参数；不猜测语法，`model_overrides` 只用于名称匹配的模型。

## 模块 4：保存或复用风格

仅在审美方向已确认、可复用规则来源明确后，按以下规则保存或复用 UTF-8 JSON；未确认草稿不落盘：

1. 使用 `~/.agents/image-prompt-styles/<kebab-case-id>.json`；目录不存在时创建。
2. 只保存可复用视觉信息，不保存主体、正文、客户名、单次背景或场景、临时动作及路线 B 的证据。
3. 已加载风格即使有本次覆盖或筛选，默认仍不写文件、不创建变体，报告源路径及本次实际覆盖。只有用户明确授权更新原风格时才修改对应字段，其他字段不变；明确要求另存时才另存。确为已确认的新风格且同名不同内容时沿用 `-2`、`-3` 变体机制，不把草稿或临时覆盖当成新风格。
4. 保存失败仍交付提示词，并报告原因和未保存状态。
5. 通用模式同样按实际确认结果填写字段：配色、构图等若是跨任务审美核心则保留；没有确认内容才留空。不得为了“通用”清空所有颜色或布局，也不得把某次画面安排泛化成偏好。

保持 `schema_version: 1` 和现有字段不变；没有内容的可选字段保持空值，不补造偏好。新维度按以下规则映射：

- `光影和色调`：主辅色、近似色号、颜色用途、饱和度和色温规则写入 `palette`；光源、方向、软硬、明度、对比度和照明氛围写入 `lighting`。
- `后期和纹理`：媒介、成片处理、颗粒或噪点、清晰度、晕光、笔触及表面质感写入 `medium_and_texture`。
- `背景`：可复用的背景视觉处理写入 `visual_style`，空间层次、背景布局和主体分离方式写入 `composition`；具体地点、环境、天气及单次背景或场景属于任务内容，不写入风格 JSON。

```json
{
  "schema_version": 1,
  "id": "style-id",
  "name": "用户可识别的风格名称",
  "summary": "一句话视觉描述",
  "visual_style": [],
  "medium_and_texture": [],
  "palette": {"colors": [], "rules": []},
  "lighting": [],
  "composition": [],
  "typography": {"mode": "unspecified", "rules": []},
  "characters": [],
  "decorations": [],
  "negative_defaults": [],
  "model_overrides": {}
}
```

## 模块 5：输出格式

使用与用户输入相同的语言，除非用户指定其他语言。

- 最终交付以一块连续的 `text` 代码块为主体：规则、任务、适用负向约束和模型参数均在同一块，不让用户拼接多个区域。目标平台即使另设负向或参数输入框，也只在本块标清内容，不把成品拆散。
- 多图属于同一任务时在块内逐图列出；用户明确需要多份独立提示词时一份一块，每块完整，不以“其余同上”依赖另一块。
- 块外仅补充必要假设、限制、本次风格覆盖摘要及保存／复用的绝对路径或失败原因；没有内容的栏目省略，不再重复正向、负向、参数或整份验收清单。风格 JSON 写文件，不额外要求用户复制它才能使用成品。
- 路线 B 的证据、候选解释和确认过程在确认阶段展示；不塞入最终执行提示词。未确认草稿与已确认成品明确区分。

## 质量检查

输出前确认：

- 路线 A 仅确认实质缺口，已明确和不适用内容未重复采访；维度清单仅用于覆盖检查。路线 B 的证据与集中确认按其参考文件执行。
- 原图来源内容、目标任务内容和可复用风格已正确拆分，未把路线 B 证据或一次性内容写入风格文件。
- 每份成品只有一个连续 `text` 代码块，包含全部必要规则、任务、负向约束及适用参数，无空栏目或块外依赖；具体任务内容齐全，多图逐图对应；通用模板明确另需任务输入。
- 视觉维度、文字密度、正向规则、禁止事项和 `不适用` 状态彼此一致；模型语法受支持，装饰性形象使用“符号或贴图”。
- 负向内容在块内 `[禁止事项]` 中具体表达，无分散重复清单；风格文件兼容 `schema_version: 1`，且已报告路径或保存失败原因。
- 复用时未覆盖条目保持原文及相对顺序，本次覆盖与受影响禁项一致；源文件未被默认改写，未产生无意变体。
- 通用模式保留用户确认的跨任务审美核心，配色与构图不被一刀切删除；一次性内容和未确认场景安排没有混入风格。
