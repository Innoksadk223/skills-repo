# 通用模式：按审美意图筛选

用户声明「通用风格／通用模式」时进入；未声明时默认具体单图任务。通用模式与路线 A（文字）或路线 B（识图）正交，不增加一套采访。

## 筛选原则

通用不是删掉颜色、照明与构图，而是保留用户希望跨任务延续的视觉关系，去除仅属于某次内容的安排。

- **保留已确认的审美核心**：媒介与表面质感、形状与线条、色彩关系、照明倾向、文字表现、密度与构图习惯等。用户确认配色或留白位置就是风格特征时，它们同样可复用。
- **剔除一次性内容**：主体身份、正文、地点、临时动作、具体天气与时段、某次场景中的摆位和数据。不能因参考图恰好用了某种安排，就推断用户永远偏好它。
- **不确定时按影响处理**：会改变审美核心的归类，询问用户“以后换主题也要保留这个效果吗”；用效果解释，不让用户学习“光质／光照方案”等术语。低影响细节沿已确认方向处理，不新增必问字段。

同一个特征可能是核心，也可能只是场景安排；依据来自用户意图与确认，不来自字段名称。保留什么和排除什么都应能说明理由，不用抽象形容词替代可见规则。

## 与路线及已有风格衔接

- 路线 A：维度清单只作覆盖检查，相关实质缺口合并确认，已明确与不适用内容不重问。不要求提前填写未来主体、动作或场景。
- 路线 B：先区分可见事实、候选解释、已确认偏好；将跨任务保留的取舍与目标内容选择并入正常的一次集中确认。修正后仍须检查；新增关键冲突按路线 B 暂停，不伪造确认。
- 已加载风格：用户选定的可复用条目作为基线。当前明确筛选或覆盖只影响此次成品；没有冲突就不额外追问，也不清空 `palette` 或 `composition`。意图不明且影响核心时，把最小取舍并入当前路线的确认。
- 已加载风格即使经过筛选，默认不写源文件、不创建变体。只有明确更新或另存授权才能持久化变化；未覆盖条目的原文及相对顺序保持稳定。

## 组装与保存

- `[风格规则]` 写入已确认的可复用视觉规则；负向约束、可靠参数如适用，放在同一连续 `text` 代码块中。
- `[任务]` 明确这是通用风格模板，下游另需主题、必要内容与约束；收到任务后才创作，缺少关键输入时先询问。不用占位符或对当前对话的引用冒充完整单图任务。
- 保持 `schema_version: 1` 和主文件全部字段；颜色写入 `palette`，照明写入 `lighting`，构图关系写入 `composition`，材质处理写入 `medium_and_texture`，其他按主文件映射。只在确无内容时留空，不按字段整类排除。
- 确认且来源明确的新风格按主文件自动保存机制处理；同名冲突、已有风格复用与明确更新均遵循主文件，未确认草稿不保存。

完整文字示例见 [通用模式示例](generic-mode-example.md)。
