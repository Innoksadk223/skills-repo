# 路线 B：识图倒推

仅用于用户提供的成品图片或截图。按 `SKILL.md` 的审美确认规则提炼候选理解，不先展示空模板。不要把粘贴的成品提示词文本或文字化走查条件当作实际视觉证据。

## 分析图片

先确认输入可读取且确为图片；不可读取时说明无法分析并停止，不猜测、不转入逐组采访。

按与路线 A 相同的十组逐项分析，但此阶段不向用户提问：

| 需求组 | 从图片提取的内容 |
| --- | --- |
| 输出目标 | 可见的画面类型、可能用途与受众；无法判断的模型或交付物保持未指定 |
| 主体与动作 | 识别具体主题、主体、动作、关系、姿态、表情和关键属性，并区分原图来源内容与用户的目标任务内容 |
| 背景 | 识别环境、地点、时间、天气、空间层次、背景元素和主体分离方式，并区分一次性背景内容与可复用背景处理 |
| 视觉风格与媒介 | 审美方向、时代、写实程度，以及摄影、绘画或三维媒介 |
| 构图与画布 | 宽高比、景别、视角、区块、层级、主体位置、留白和动势 |
| 光影和色调 | 可见主辅色、近似色号、颜色用途、明度、饱和度、色温、对比度、光源、光线方向与软硬、整体氛围 |
| 后期和纹理 | 可见成片处理、颗粒或噪点、清晰度、晕光、笔触、纸张、画布或材质表面质感 |
| 内容结构与文字 | 信息区块、顺序、密度、表格图表、字体表现、语言和可读性；具体正文区分为原图来源文案或目标任务文案 |
| 符号或贴图与装饰 | 类型、视觉特征、功能、动作、位置、图案、边框及遮挡关系 |
| 负向约束与质量边界 | 从成品反推会破坏该风格的反向特征，以及可见结构边界 |

内部用十组检查覆盖；对外只展示与判断有关的证据和缺口，不要求十行表全部填满。分开记录：

- **可见事实**：画面中能指出位置的形状、色块、明暗、笔触与内容。近似色号只作估计；不能仅凭外观证明实际媒介、制作技术、光源布置、地点身份或年代，相关判断属于候选解释。截图不证明交互、响应式或技术实现。
- **候选解释**：这些特征可能形成什么感受、可能接近何种风格、哪些可跨任务复用；注明依据与不确定性。没有可靠归属时描述特征，不编造流派名。
- **用户已确认偏好**：用户明确选定保留或改变的特征、目标内容及其授权范围。只有真实授权后才能记录 `授权推断`，不能把未观察到的必需内容自动标成已授权。

非必要未知项保持未指定，不适用项跳过；目标主体、动作、完整文字等关键内容缺失时留给集中确认，不虚构品牌、正文、数据、模型能力或画外元素。

## 拆分规则

1. **可跨任务复用**：视觉语言、媒介、光影和色调、后期和纹理、背景处理、构图、文字表现、符号或贴图、装饰及负向默认值。用于提示词和风格 JSON。
2. **原图来源内容**：原图主题、主体身份、正文、客户名、专有数据、单次背景、场景和动作。除非用户选作目标，否则只在需求摘要中列为已剔除，不进入提示词或风格 JSON。
3. **目标任务内容**：新图主题、主体、完整文案、背景、场景、动作和关系。必须进入提示词但不进入风格 JSON；多图逐图对应。

保留 schema 的 `characters` 字段名；提示词中统一称“符号或贴图”。

## 集中确认与修正

分析阶段不提问。完成覆盖检查、三类拆分及 `SKILL.md` 的冲突检查后，集中展示：

1. 关键可见事实及位置依据、候选审美理解，以及已明确的用户偏好；有歧义时给少量效果对照，不要求选流派名。
2. 建议跨任务保留的规则、被剔除的原图内容、目标任务内容，以及高影响冲突与建议取舍。具体任务内容缺失时，在此询问沿用哪些原图内容或补充什么；通用模式无需编造未来主体与场景。
3. 信息足够时提供一块自包含提示词草稿及风格字段摘要；关键内容缺失时只列已知规则与缺口，不伪造完整草稿。

正常路径用一次批量确认完成上述事项，不转入路线 A 逐组采访。确认后或收到修正后，均重新检查内容完整性、审美一致性、正负向冲突与保存范围：

- 信息齐全且一致：应用已确认修正，按主文件保存规则交付，不再问例行确认。
- 修正引入新的关键缺口或互斥要求：明确暂停成品及保存，说明最小阻塞项，请用户补齐或取舍；解决后重新检查，不为维持“一次确认”编造结果。
- 用户拒绝或图片不可读：停止，不保存未确认草稿。

批量确认只是交互预算，不是跳过修正检查的理由。文字条件走查只验证这些分支，不是实际识图测试。
