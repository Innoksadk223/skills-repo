# Intent Normalizer

## 核心目标

把用户不完整、表象化、非专家化的表达，转成可执行任务；不要顺着不成熟描述盲目开工。

原则：

- 先还原真实目标，再处理用户提出的方案。
- 先用对应领域专家视角理解，但不要把专业术语丢给用户选择。
- 只补齐执行必需信息；不替用户扩需求。
- 能安全假设就明示假设并继续；会改变路线、成本、风险、交付物的问题才追问。
- 规范化不是交付终点；契约足够清楚时立即执行。

## 工作顺序

日常短任务只在脑中完成；复杂、多轮、需恢复时才落盘到 `state/intent-normalizer/<intent_task_id>/task_contract.md`。用户原始请求变化时必须创建新的 `intent_task_id`。

1. **专家模式**
   - 领域镜头：判断主领域、交叉领域和专家角色。
   - 表象翻译：把生活化说法翻译成领域里的真实需求。
   - 专家判断：识别目标、方案、交付物、约束或风险混淆。
   - 用户友好确认：只有答案会改变路线时，才用非术语问题确认。

2. **输出决策**
   按优先级只选最小动作：
   - 安全/不可逆：删除、覆盖、公开发布、付费调用、修改系统环境，先暂停确认。
   - 方向错误：先一句话纠偏，再给更合适路线。
   - 真实分叉：给最多 3 个生活化选项，说明推荐项、效果和代价。
   - 用户要求先对齐：只展示影响决定的精简契约或选项摘要。
   - 关键缺口：只问 1-3 个会改变交付物或执行路径的效果题。
   - 可安全假设：明示默认假设，内化契约，直接执行。

3. **规范化并推进**
   把用户原话改写为可执行任务契约。能执行就继续调用相应工具或 skill；必须追问才暂停。

不要默认展示完整契约。完整契约是 Agent 的执行依据，不是每次给用户看的交付物。

## 判断规则

| 情况 | 动作 |
| --- | --- |
| 不影响首版结果 | 写成默认假设，继续执行 |
| 影响路线/成本/交付物/风险 | 问 1-3 个效果题 |
| 安全或不可逆 | 暂停确认 |
| 用户方案偏离目标 | 先纠偏；只有一个明显最优解时直接执行，有真实取舍时让用户选 |
| 用户要先梳理/评估/对齐 | 输出精简契约；下一步明确则继续，否则停在确认点 |
| 已是明确单步命令、闲聊或解释概念 | 不触发本技能 |

## 提问方式

面向非专家用户，问效果题，不问术语题。

- 不问：“你要前端还是全栈？”
- 改问：“只是浏览器里打开的页面，还是需要别人登录、保存数据？”
- 不问：“你要 SaaS 架构吗？”
- 改问：“这是自己临时用，还是给多人长期使用？”

问题必须满足：答案会改变下一步做法；用户能凭生活经验回答；每题附一句原因。超过 3 个问题时，只问当前阶段最关键的问题。

## 压力自检

输出前快速检查：

- **是否只复述了表象？** 用户只说愿望、感受或粗糙方案时，先用专家视角翻译成真实目标和交付物。
- **是否在契约表演？** 用户要结果时，不展示完整契约；用内部契约推进。
- **是否在过度追问？** 答案不影响首版交付物、成本、风险或不可逆动作时，写成默认假设。
- **是否在问术语题？** 需要用户懂技术分层、架构名词或专业流程的问题，改成使用场景/效果题。
- **是否纠偏后卡住？** 只有一个更合理路线就说明并执行；存在真实取舍才让用户选。

## 输出模板

需要追问时：

```markdown
我先确认 [1-3 个问题]，因为这些答案会改变最终做法：

1. [问题]
   原因：[为什么会改变执行]
```

可以继续时，内化或精简展示任务契约：

```markdown
# 规范化任务契约

## 用户真实目标
[一句话]

## 专家视角
- 领域：
- 角色：
- 表象翻译：
- 关键判断：[1-3 条]

## 可执行任务
- 交付物：
- 范围：
- 输入：[没有则写“无”]
- 输出：
- 约束：
- 不做：

## 默认假设
- [可安全采用的假设]

## 验收标准
- [ ] [可判断标准]

## 风险与未确认项
- [不阻塞执行但需要说明的风险]

## 下一步
[直接执行 / 先确认问题 / 给出路线选择 / 暂停]
```

使用规则：用户只要最终结果时不展示完整契约；需要对齐范围、成本或交付物时，只展示会影响决定的部分。执行中发现假设不成立，先更新契约，再继续或追问。

## 示例

用户：我想要设计一个网页，会动的那种。

规范化要点：

- 真实目标：做一个浏览器可打开、有动效和交互感的网页原型。
- 专家视角：网页设计 / 前端实现；“会动”通常指页面动效、转场或交互反馈，不等于复杂应用或动画引擎。
- 关键判断：未提登录、数据库、后台，所以不默认扩展；首版适合 HTML + CSS + JavaScript 静态单页。
- 交付物：本地可打开的静态网页，含布局、视觉风格、CSS 动效、少量 JavaScript 交互。
- 不做：账号系统、后台接口、数据库、上线部署。
- 验收：页面能打开；主题明确；至少 2-3 处动效或交互；不需要服务器运行。
