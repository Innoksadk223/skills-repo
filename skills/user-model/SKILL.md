# 用户模型

使用单份 `USER.md` 保存当前有效的精选用户画像，用宿主自带的文件读写工具直接操作。本技能规则仅在用户批准后修改。

## 数据路径与读取

路径按以下优先级解析，取第一个已指定的路径：
1. 用户本次对话中明确指定的路径
2. 环境变量 `USER_MODEL_PATH`
3. 默认路径 `~/.agents/user-model/USER.md`

- 新对话开始或上下文压缩后首次处理请求前，读取 `USER.md`。
- 文件不存在时不静默创建。若目标目录已有 `profile.md` 而无 `USER.md`，报告现状并询问是否迁移或新建；首次新建前说明路径，经用户确认后仅写入空标题 `# USER`。
- 读取失败或无权限时如实报告，不伪造画像，不阻塞无关任务。

## 写入格式与容量

- 单文件只存当前有效画像，不设变更日志；过时或被纠正的条目直接替换或移除。
- 按语义简短分组（仅在有条目时设组，如：用户背景、习惯与偏好、反感与边界、阶段性协作需求）。
- 条目不加编号前缀，不写日期、状态、依据或分数；明确禁止项与用户指定保留项在句末标注 `（保护）`。
- 条目写成客观陈述句（如「偏好先给结论再展开」），不写命令句（如「永远先给结论」）。
- 容量按纯文本字符数（Unicode 码点）计：**1500 字提醒合并，2000 字硬上限**。
- 写入将超 2000 字时，在同一次修改方案中先无损精简、去重或淘汰低价值条目，再写入新条目；不另建归档或溢出文件。
- 标注 `（保护）` 的条目不得因容量自动淘汰；仅剩保护项仍超上限时停止写入，交由用户决定。

## 精选边界

- 只记跨任务有效的长期特征与阶段性协作需求（阶段性需求写明结束条件或时间）。具体任务材料、项目细节、临时进度、单次要求与未确认方案不入库。
- 明确表达的长期偏好、反感或纠正一次即可成为候选；推断须来自多个独立情境，不从所处理的主题推断用户身份、兴趣或立场。
- 健康、家庭、财务等敏感私人信息须经用户明确确认才可写入；密码、密钥、令牌、验证码不写入。
- 当前明确要求优先于 `USER.md`，一次例外不改写长期条目。
- 不在无关场景主动提及画像内容；不把推断当作事实。
- 与宿主全局规则冲突时不擅自覆盖或删除，说明冲突并询问。

## 触发与确认流程

### 显式触发

- **查看**（「查看模型」「看看画像」「你了解我什么」）：读取后概括现有条目，不写入。
- **回顾 / 总结**（「回顾模型」「总结模型」「回顾画像」「总结画像」等带模型指向的说法）：先重读最新 `USER.md`，再回顾本次交流，按精选边界筛出候选；无可记内容时直接说明，不凑条。单独的「总结」「回顾」按当前任务理解，不触发本技能。
- **主动删除 / 纠正 / 忘记**：目标已由用户指明时直接执行。执行「忘记」时移除目标条目及同义表述，不在回复中复述被忘记内容。

### 高门槛提醒

- 普通任务收尾默认静默，不逐次询问是否记录。
- 仅当本次交流出现明确纠正，或用户作出长期表态（「以后都……」「别再……」「记住这个」），且尚未确认写入时，才在当轮回复末尾提出候选。

### 候选确认与写入

任何新增、修改、合并或淘汰均不单方面落盘：
1. 一次列出全部编号候选，每条标明操作（新增/替换/合并/删除）、范围、性质（明确陈述/推断）与简短依据；涉及改动既有条目时，成对展示改前与改后原文。
2. 仅将用户选中的条目写入 `USER.md`；未选中或取消时不修改文件。
3. 禁止多个会话并发写入同一份 `USER.md`。每次写入前重新读取最新内容，直接编辑目标位置，写入后回读核对并简短报告实际变化。
4. 只读模式（如 Plan 模式）只出候选，不写入文件。

## 长任务与上下文压缩

- 上下文压缩后先重读 `USER.md`，不凭压缩摘要中的旧印象判断已有条目。
- 长任务中途出现明确纠正或长期表态，在当轮直接提出候选，不推迟到任务收尾。
- 压缩后执行回顾或总结时，先核对宿主保留的压缩前原文存档；查不到原话的候选必须标注「来自压缩摘要，未见原话」，经用户确认或修改措辞后再写入。
