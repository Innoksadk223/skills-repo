# 路线 A：文字需求与聚焦确认

用于只有文字需求，或加载本地风格预填后的请求。先按 `SKILL.md` 的审美确认规则理解描述，不要求用户先知道风格名，也不先展示空模板。

## 九组覆盖检查

下表只供内部防漏，不是九轮问卷。可把相关缺口合并询问，不必展示整张表；通用模板不要求把未来产品细节全部填完。

| 字段组 | 字段 |
| --- | --- |
| 输出目标 | 模式、目标执行器、交付物 |
| 产品背景 | 产品类型、平台、目标用户、核心任务、成功结果 |
| 页面范围 | 页面或屏幕、信息架构、关键流程、主要操作 |
| 内容数据 | 必须出现的文案、真实数据、状态、空态和错误态 |
| 风格偏好 | 审美方向、视觉密度、避免事项 |
| 视觉系统 | 布局、色彩、排版、图标、组件 |
| 材质质感和纹理 | 材质、表面、透明与模糊、颗粒与噪点、纹理与图案、高光与阴影、层次 |
| 体验行为 | 导航、组件状态、反馈、动效、手势 |
| 质量约束 | 响应式、可访问性、性能、技术边界、验收方式 |

## 聚焦确认

1. 直接采用用户已经明确的内容与所选风格覆盖的条目，不复述求确认、不逐组重问；明显不适用的项跳过。
2. 先找出会改变结果的审美分歧、执行模式与约束，合并本轮可独立回答的问题；依赖尚未作出的决定的问题留后。通常一轮解决，出现实质新分歧才继续，不设最低轮数或固定组数。
3. 模式已明确时直接采用；只有执行器或交付物存在不同解释时，确认 `implementation` 或 `visual`。不因看到截图而默认要实现代码。
4. 有审美歧义时用少量可感知的效果对照确认；确需推荐时说明依据，不强制选择流派。色号、圆角、阴影数值等低影响细节沿已确认方向和平台约束处理，不逐项采访。
5. 必要时在对话内标注 `已明确`、`候选解释`、`授权推断`、`待补齐` 或 `不适用`。只有用户实际授权的范围才能标为授权推断；定调不等于授权编造功能、主要操作、关键流程、文案或数据。非必要未知项保持未指定。
6. 产品名、具体页面、文案与数据、品牌标识、专有流程、项目路径和文件名属于一次性内容，只在必要摘要中说明；模板及风格文件只保留可复用规则。缺少某个具体产品不阻止生成通用模板，但模板内必须说明下游另需产品任务，不能假装已经可直接实现这个产品。
7. 模板所需方向、模式和约束已明确、审美解释获确认且无高影响冲突后，返回 `SKILL.md` 组装。用户跳过采访但仍有关键缺口时说明缺口并暂停成品；只有用户要求时交付标为未确认的草稿，不保存、不把假设写成已确认。
