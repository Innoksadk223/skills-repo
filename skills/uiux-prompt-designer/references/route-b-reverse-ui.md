# 路线 B：识图倒推

仅用于用户提供的成品界面图片或截图。按 `SKILL.md` 的审美确认规则提炼候选理解，不先展示空模板。不要把粘贴的成品提示词文本或文字化走查条件当作实际视觉证据。

## 分析界面图片

先确认输入可读取且确为图片；不可读取时说明无法分析并停止，不猜测、不转入逐组采访。

按与路线 A 相同的九组逐项分析，但此阶段不向用户提问：

| 字段组 | 从图片提取的内容 |
| --- | --- |
| 输出目标 | 可见成品类型和可能执行模式；静态截图不能证明目标是实现代码，模式不明确时留待批量确认 |
| 产品背景 | 可见产品类型、平台线索、用户任务和成功结果；具体产品与品牌标记为一次性内容 |
| 页面范围 | 可见页面类型、信息架构、主要区块、操作入口和流程线索；具体页面名与单次流程标记为一次性内容 |
| 内容数据 | 可见文案、数据密度、表格图表、状态、空态和错误态；具体文案与业务数据标记为一次性内容 |
| 风格偏好 | 可见审美方向、视觉密度和避免事项；商标及可识别品牌组合标记为一次性内容 |
| 视觉系统 | 布局、网格、色彩、排版、图标、组件、间距和层级 |
| 材质质感和纹理 | 可见材质与表面、透明与模糊、颗粒与噪点、纹理与图案、高光与阴影、层次；不推断 CSS 属性、资源来源或实现方式 |
| 体验行为 | 只记录截图中可见的导航与组件状态；hover、手势、反馈、动效和隐藏流程无法从静态图直接证明 |
| 质量约束 | 记录可见的对比度、触控尺寸、内容可读性和布局边界；响应式、性能、技术栈、文件边界和完整可访问性无法直接证明 |

内部用九组检查覆盖；对外只展示与判断有关的证据和缺口，不要求九行表全部填满。分开记录：

- **可见事实**：截图中能指出位置的区块、色块、排版、材质表现和当前状态。对比度、尺寸等未经测量只能描述观感，不能声称已达到某项可访问性指标。
- **候选解释**：可能的产品用途、审美感受、风格归属及可复用规则；注明依据与不确定性。自创或混合审美不强行归类。
- **用户已确认偏好**：用户选定的模式、风格核心与修正、实际授权范围。只有真实授权后才能记录 `授权推断`。

静态截图不能证明交互、响应式或技术实现，也不能证明动效、性能、完整可访问性与画外流程。主文件要求的平台与可访问性底线是对未来执行的约束，不是对截图的事实判断；不把它们伪装成识图结论。其余未知项保持未指定，不适用项跳过，不虚构业务能力、文案或数据。

## 拆分规则

1. **可跨任务复用**：视觉原则、适用场景、色彩、排版、布局、组件、材质与纹理、可见交互、动效边界、可访问性、实现提示和反模式。用于提示词与风格 JSON。
2. **一次性任务内容**：产品名、品牌标识、具体页面、业务文案与数据、客户名称、专有流程、项目路径和文件名。只在需求摘要中列为已剔除，不进入提示词或风格 JSON。

不得把第三方截图中的商标、专有表达或可识别品牌组合改写成通用规则。

## 集中确认与修正

分析阶段不提问。完成覆盖检查、两类拆分及 `SKILL.md` 的冲突检查后，集中展示：

1. 关键可见事实及位置依据、候选审美理解，以及已明确的用户偏好；有歧义时给少量效果对照，不要求选流派名。
2. 建议跨任务保留的规则与被剔除的一次性内容；未知模式的建议及理由，高影响冲突与建议取舍。截图并不自动授权复刻品牌或隐藏行为。
3. 信息足够时提供一块通用提示词草稿及风格字段摘要；模板方向或模式等关键内容缺失时只列已知规则与缺口，不伪造完整草稿。没有具体产品任务不妨碍生成模板，但块内必须声明下游另需任务输入。

正常路径用一次批量确认完成上述事项，不转入路线 A 逐组采访。确认后或收到修正后，均重新检查模板完整性、审美一致性、正负向冲突与保存范围：

- 信息齐全且一致：应用已确认修正，按主文件保存规则交付，不再问例行确认。
- 修正引入新的关键缺口或互斥要求：明确暂停成品及保存，说明最小阻塞项，请用户补齐或取舍；解决后重新检查，不为维持“一次确认”编造结果。
- 用户拒绝或图片不可读：停止，不保存未确认草稿。

批量确认只是交互预算，不是跳过修正检查的理由。文字条件走查只验证这些分支，不是实际识图测试。
