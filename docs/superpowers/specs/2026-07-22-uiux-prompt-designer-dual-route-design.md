# UI/UX Prompt Designer 双路线流程设计

> 本次修订：审美确认、聚焦采访、单块输出与风格复用。现存技能本体未删除；本文同步当前九组覆盖维度，替代初版的采访预算、组装与验证约定，不用于从旧稿覆盖技能。

## 目标与文件边界

从文字描述或成品界面图确认用户审美，产出可复用的 UI/UX 规则模板。模板的规则与输入约定自包含，但下游还需另行提供产品任务；不把模板冒充包含具体页面、文案和数据的完整执行指令。

- [SKILL.md](../../../skills/uiux-prompt-designer/SKILL.md)：路线、审美确认、两种模式、冲突、组装、保存和质量检查。
- [route-a-interview.md](../../../skills/uiux-prompt-designer/references/route-a-interview.md)：九组内部覆盖检查与聚焦确认。
- [route-b-reverse-ui.md](../../../skills/uiux-prompt-designer/references/route-b-reverse-ui.md)：实际界面图证据与集中确认。

保留 `implementation`／`visual` 两种模式与 schema v1；不新增运行框架、状态目录、跨技能依赖或交付模式。

## 路线与审美确认

- 指定本地风格时先加载，再按输入选择路线；只有文字走 A，有成品图片或截图走 B。直接搭建、修改或审查界面转交执行能力；不倒推粘贴的成品提示词文本。
- 共用过程：提取描述／观察证据 → 概括审美意图 → 必要时提出少量候选解释 → 用户确认或纠正 → 转译视觉规则。
- 区分整体感受、形成感受的可见特征、希望跨任务保留的核心。不要求用户知道风格名；可靠名称只作辅助，自创或混合审美用描述性名称，不杜撰流派归属。
- 抽象感受落到形状、线条、色彩关系、材质、布局、排版和密度等相关维度；少量可感知的效果对照用于确认真实分歧，不建立新的术语问卷。
- 审美推断不授权编造产品功能、主要操作、关键流程、文案或数据；不为了生成通用模板追问所有未来产品细节。

### 路线 A

九组只作内部覆盖检查，不对应固定轮数或提问顺序。已明确内容直接采用，不适用项跳过；合并模式、审美与约束中的实质缺口。通常一轮解决，只有实质新分歧才继续。必要方向与模式尚不明确时暂停成品；没有具体产品本身不妨碍生成通用模板。

### 路线 B

仅基于实际可读取图片；不可读时停止，不伪造证据。分析阶段不提问，分开记录可见事实、候选解释和用户已确认偏好。静态截图不能证明交互、响应式或技术实现，也不能证明动效、性能、完整可访问性和画外流程。未经测量的尺寸、对比度只描述观感，不声称达到指标。

拆分可复用规则与一次性产品、品牌、页面、文案和数据。正常路径集中一次展示关键依据、审美理解、模式建议、保留范围、冲突、缺口，以及信息足够时的单块草稿，批量确认；不要求九行表全部填满，不转成逐组采访。

确认或修正后均检查模板完整性、一致性、正负向冲突与保存范围。无新缺口则直接交付；出现新的关键缺口或互斥要求，说明最小阻塞项并暂停，请用户补齐或取舍，解决后再检查。确认次数不能凌驾于正确性。拒绝则停止，不保存未确认草稿。

## 单块输出与执行模式

每份成品使用一个连续的 `text` 代码块，包含全部必要规则、模式、下游输入约定、负向约束和可靠参数；不依赖另一份清单或当前对话。

- 核心标题：`[设计规则]`、`[体验规则]`、`[交付规则]`、`[任务]`。
- 按需标题：`[内容规则]`、`[禁止事项]`；可靠视觉模型参数如需提供，完整放入 `[交付规则]`，不另设空栏目。
- `[任务]` 明确通用模板定位，要求另行提供产品任务、页面范围与必要内容约束，缺少关键输入时先询问，不编造产品。
- 模式明确时不重复确认；模式改变交付要求及规则表达，不改变双路线。用户要求两种模式时一份一块，每份完整，不能以“其余同上”引用另一份。
- 块外仅保留必要假设、限制、实际覆盖或模式筛选摘要、保存／复用路径或失败原因；证据与候选解释在确认阶段展示。

### implementation

先检查现有项目，保留技术栈、设计令牌、组件库、路由、数据和资产，不重建脚手架；只改授权文件。实现必要组件状态、响应式、键盘导航、语义、标签、对比度、触控目标和减少动效；保留性能、真实内容、运行方式与最小验证，不新增未授权依赖、后台、登录、数据库或部署。

### visual

描述可见结果：视口、构图、网格、留白、密度、颜色、排版、图标、材质与组件关系，以及任务需要的选中、焦点、错误或空态表现。不用代码、CSS 或性能术语替代画面规则，不把静态稿当作已实现交互的界面。多个视口／状态由下游任务指定范围后分别呈现，缺必要输入时先确认。

保留可读文字、明确层级、状态不只靠颜色区分等可见底线；不编造商业证明、数据或乱码。只在指定视觉模型时提供可靠参数。工程与可访问性底线不能被审美取消，但它们是未来执行约束，不是截图已经达标的证据。

## 风格复用与保存

- 当前明确要求仅覆盖冲突条目及受影响禁项，未覆盖的适用条目保留原文与相对顺序；不静默润色整个风格段。
- visual 只纳入可见结果条目；不适用的行为、动效实现或工程条目说明后排除，不改源字段。转译需要新设计决定时并入正常确认，不把推断当偏好。
- 加载风格后的本次覆盖或模式筛选默认不写源文件、不创建变体；只有明确更新或另存授权才持久化变化。
- 已确认且来源明确的新风格自动保存，同名不同内容沿用变体机制；未确认草稿、临时覆盖及两种模式不作为新风格。
- 保留用户确认的跨任务配色、构图、组件及体验规则，剔除一次性内容与未经确认的场景安排；不按字段整类清空。
- 保留 `schema_version: 1` 及现有全部字段，映射以主文件为准；`implementation_hints` 仅用于 implementation，`atmosphere` 继续只作旧文件兼容保留。保存失败仍交付模板并报告未保存。

## 验证与入口

1. 用可用文件工具或标准库检查 frontmatter、相对引用、旧规则残留、单块契约与字段兼容；schema 与修改前快照比较。不假定存在未安装的校验脚本。
2. 少量文字样例覆盖不知道风格名、自创审美、本次覆盖以及两种模式；展示输入、关键确认、成品与判定依据。检查 visual 没有技术行为承诺，implementation 没有丢失工程与体验底线。
3. 识图确认与修正用文字条件走查时，明确不是实际视觉测试；不得据此报告生图质量、模型理解率或真实界面可用性。
4. 不改真实风格库，不调用独立模型、生图或前端构建；需扩展验证时另取授权。
5. 以独立快照保护未跟踪技能，核对无关改动不变；仅恢复缺失的 `~/.agents/skills/uiux-prompt-designer` 到仓库本体的链接，不运行全量安装器，不新增 Pi 专属重复入口，不重建已正确的其他链接。需要提交时先确认精确文件范围。
6. 最终由用户刷新技能发现，确认入口可见及审美确认、整块复制效果符合预期；文件检查不代替人工验收。
