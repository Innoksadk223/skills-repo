# Image Prompt Designer 双路线流程设计

## 目标

将 `image-prompt-designer` 从单一八组采访改为两条路线汇聚到同一交付结构：一个自包含的四节提示词和一个兼容现有 schema 的风格 JSON。

## 文件边界

- `skills/image-prompt-designer/SKILL.md`：路线选择、共用四节模板、冲突处理、风格保存、输出格式、质量检查。
- `skills/image-prompt-designer/references/route-a-interview.md`：八组需求单及逐组采访。
- `skills/image-prompt-designer/references/route-b-reverse-image.md`：仅图片输入的视觉规则倒推与单次批量确认。

不新增脚本、状态目录或 schema。路线状态只保留在当前对话。

## 路线选择

- 成品图片或截图：路线 B。
- 只有文字需求：路线 A。
- 指定风格库已有风格：加载预填后走路线 A。
- 直接要求生成图片而非设计提示词：转交对应执行能力。
- 粘贴现成提示词文本：说明不支持倒推，不进入两条路线。

两条路线进入后都先展示四节结构说明；展示模板不算提问。

## 路线 A：从零采访

保持八组需求单与每轮一组的采访机制。已有资料只用于预填，仍需显式确认。八组均不再是 `待确认` 后，进入共用冲突处理与提示词组装。

## 路线 B：识图倒推

仅接受图片。按八组需求单维度提取可见视觉证据，覆盖视觉风格与媒介、配色、构图与画布、内容结构与文字、符号或贴图与装饰、负向特征等。无法从图中确定的项目标记为 `授权推断` 并写明依据，不虚构。

将可跨任务复用的视觉规则送入提示词和风格 JSON；剔除图片中的具体主题、正文文案和其他一次性任务内容。所有提取结果、拆分结果、冲突取舍和四节提示词草稿一次展示，用户一次确认即视为八组完成。用户在该次回答中提出修正时，直接按修正产出最终版本，不再追问；用户拒绝继续时停止。路线 B 全程不得触发路线 A 的逐组采访，也不得追加第二次提问。

图片不可读或并非图片时停止路线 B 并说明原因，不伪造证据。

## 共用提示词模板

最终提示词始终保留四个标题：

1. `[风格规则]`：视觉风格、媒介、画布、配色及用途、符号或贴图、装饰。
2. `[内容规则]`：信息组织、布局、表格图表、文字规则和输出语言。
3. `[禁止事项]`：任务相关负向约束；没有时写“无额外禁止事项”。
4. `[任务]`：使用通用指令，根据以上规则为用户提供的主题或内容创作适合目标用途的图像。

提示词只使用已确认需求，不含角色设定、角色扮演或算力类元指令、占位符语法、一次性主题或正文。使用“符号或贴图”，不使用“吉祥物”。

## 共用尾部

- 冲突处理：路线 A 沿用现有行为；路线 B 把全部冲突取舍并入唯一一次批量确认。
- 风格保存：保持 `schema_version: 1` 的现有字段与保存、复用、变体和失败报告规则。
- 输出语言：跟随用户输入，除非用户指定其他语言。
- 输出格式：保留需求摘要、正向提示词、负向提示词、模型参数和风格文件。正向提示词承载完整四节成品；负向提示词不重复清单，只写“已并入成品提示词的 `[禁止事项]`”。路线 B 的需求摘要列出各维度证据、授权推断依据和被剔除的一次性内容。

## 验证

1. 静态检查路线引用、四节标题、禁用词、提问预算和原 schema 字段。
2. 路线 B 以可爱手写笔记信息图做文字化走查：仅一次批量确认，输出四节提示词和字段完整的风格 JSON。
3. 路线 A 以“化学复习笔记信息图提示词”做文字化走查：保持八组采访并输出同构提示词。
4. 对照 `~/.agents/image-prompt-styles/cute-handwritten-study-notes.json` 做字段级完整性检查。
5. 运行安装脚本同步，并确认仓库版与 `~/.agents/skills/image-prompt-designer/` 无差异。
6. 使用修改前快照检查范围，因为该技能目录当前整体未被 Git 跟踪。
